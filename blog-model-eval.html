AI 生成结果的评测方法

2026年11月 · 方法论整理 · 从四篇实测日志里抽出判据、分档与验收口径

判据四层 三级分档 可复测描述 跨平台对照 版本回归 拓扑与 UV

这一页解决什么问题

前面几篇是逐个工具、逐次生成的实测记录：Tripo 的步枪拓扑、Meshy 的智能 topo 面数、混元的节点管线、AI 三维模型的使用日志。每一篇都在判断好坏，但判据散在段落中间，读者要读完四篇才能拼出「我到底按什么标准判」。

这一页不再测新工具，而是把那些判断抽成一套可以交给别人复用的口径：看哪几层、怎么分档、问题怎么写才算说清楚、做什么样的实验才能把问题暴露出来。

落到一句话上，我判一个生成结果只问四个问题：

  • 数据干不干净——拓扑、UV、法线、水密性、尺度，能不能直接进引擎；
  • 形体对不对——比例、结构、部件边界、有没有穿模和黏连；
  • 表现像不像——材质、贴图投影、光照关系、风格是否统一；
  • 要花多少工——从生成结果到可用资产，中间还要投入多少人工。

判据四层：从数据到任务

同一个模型，站在不同岗位上看到的毛病是不一样的。纯美术看形体，纯算法看指标，而能同时说清「这里不对」和「为什么不对、该怎么修」的人最少。所以我把判据按「离数据的距离」分成四层，每层的检出手段也不同。

层 看什么 典型症状 检出手段
L1 数据层 拓扑、UV、法线、水密性、尺度轴向 非流形边、零面积面、n-gon、UV 接缝重叠、texel density 不均、缩放朝向不统一 脚本批量查 + 抽检
L2 形体层 比例、结构、部件边界、遮挡关系 比例失调、几何变形、部件黏连、多余结构、穿模 对照参考图人工判
L3 表现层 材质、贴图投影、光照一致性、风格一致性 贴图拉伸、投影错位、风格跑偏、光照关系混乱 与参考图并排比对
L4 任务层 可用度、返工成本、进管线路径 能看不能用、修的成本高于重做 按档位判定

分层的好处是：L1 的问题可以量化、可以写脚本兜住，L2 和 L3 才需要人眼，L4 是给项目做决策用的。把这三类混在一起谈，就变成了「感觉不太行」——没法验收，也没法复测。

三级分档：可用 / 可修复 / 不可用

我在使用日志里一直是按可用度分档的，原话是「整体按可用度分档，这套工具生成的多是可修复档，圆滑、封口、UV 都要走一遍后期」。把这条口径固定下来，就是三档：

档位 判定标准 典型表现 处置
A 可用 数据层零缺陷，形体与风格达标 四边面均匀、水密、UV 无重叠、尺度归一 直接进管线
B 可修复 形体正确，问题集中在数据层且可批量或局部修 角落破面、n-gon、UV 接缝重叠、圆形物体带棱角、底面未封口 脚本清破面 + 手工重拓扑 / 重展 UV
C 不可用 形体或结构错，修的成本高于重做 部件黏连无法拆分、比例崩坏、体素化、关键部位（如枪口）严重变形 弃用，换输入或换工具
为什么要分档而不是打分：百分制会让人纠结 72 分和 75 分的差别，而实际决策只有三种——直接用、修一修用、别用。分档逼着回答「修哪几步、修完能不能用」，这比一个分数有用得多。

验收口径：「改到……才算完」

这是我从步枪拓扑那次测试里固定下来的句式。描述问题的同时，把「什么状态算修完」一起写进去，一句话就把主观判断变成了可验收的完成条件。以下七条来自 Tripo 步枪低模案例（6000 面设置）的真实记录：

问题 成因判断 验收条件
冗余布线 面片密度分配不均，跟着图像明暗和高频细节走线，平坦处也乱加线 改到能均匀布四边面、顺着形体方向走线、去掉无用边缘循环才算完
角落隐藏破面 非流形边（开放边），转角处没焊死 改到破面全部封口、法线烘焙不再出黑边黑痕才算完
平面误判加面 曲面细分误判，把贴图明暗变化当成几何起伏 改到平面回归最小面数、只按真实凹凸加线才算完
布线不直 没顺着形体主方向和轴向布线 改到主方向线拉直、环形线顺形、UV 展开与烘焙不再出问题才算完
五边面及以上 补洞与三角化留下的不规则多边形 改到模型里不存在任何大于四边的面才算完
面数超限且分布不合理 面数预算没按重要性分配，面堆在次要部位，关键部位反而欠采样 改到关键部位保留足够细节、次要部位压面、整体不再超预算才算完
多组件拆分极差 部件拆分能力缺失，只生成一整块表面，没有部件边界与内部结构的概念 改到各部件能按材质和结构干净分开、单独选中、不再黏连才算完

这个句式的价值在最后半句。「角色不像」是感受，「部件按材质分开、单独选中、不再黏连」是可以当场验证的——两者之间的差距，就是评测能不能落地。

可复测描述：位置 + 现象 + 量级 + 归因

一条能被工程师直接拿去修的描述，至少要带四样东西：哪里出的问题、看到什么现象、偏差多大、可能是什么原因，最后附上复测方式。三个真实例子：

例一：超面与预算错配

设置 10000 四边面，实际生成 11355 个，超出约 13.55%；更严重的是多出来的面分配在枪托等不需要高细节的位置，而枪口等关键部位反而比 6000 面版本变形更严重。
复测方式：固定同一输入图与同一面数设置重复生成，统计实际面数与关键部位形变量。

例二：版本退化

同一张卡通单图，8 月生成的版本细节更多但属于「添油加醋」式的过度生成——原图没有的纹理与装饰被强行加上，并出现明显拉伸变形，形状严重偏离原图；4 月 7 日版本虽然棱角分明、细节粗糙，但基本形状与比例是对的。结论是生成逻辑在这段时间里出现退化，新版本倾向于添加无关细节，却丢失了最基础的形状还原能力。
复测方式：固定输入图，跨月份重跑同一条用例，按「形状还原」与「细节增益」两个维度分别判。

例三：连续生成劣化

同一套渲染提示词，Tripo 生图连续生成时只有第一次效果最好，第三次之后画面明显油腻、锐化过度、细节繁琐到不适；同时四张输出全是拼接大头照，无法理解渲染类提示词应当产出怎样的整体效果。
复测方式：同一提示词连续生成 N 次，记录从第几次开始出现劣化，并标注劣化的具体表征。

反例对照：「这个角色不像」——没有位置、没有量级、没有成因、没法复测，只能得到一句「好的我们再看看」。同样的问题写成「第 3 秒左肩塌陷、锁骨与肩胛连接处贴图拉伸，推测骨骼权重溢出，换 3 个随机种子验证是否稳定复现」，才进入可修的状态。

四类对照实验：让问题自己暴露

单次生成只能说明「这次行不行」，对照实验才能说明「稳定不行在哪」。我实际做过四类：

类型 做法 暴露了什么
跨平台对照 同参考图分别喂 Meshy 与 Tripo，比写实人物单图生成 高模上限差约 40 倍（Meshy 约 50 万三角面，Tripo 约 1985 万）；Meshy 约 1 分钟出图，Tripo 需 300～400 秒；多部件拆分 Meshy 明显更干净，Tripo 与混元经常拆崩
版本回归 同一张图隔月重跑，比 8 月与 4 月 7 日两个版本 识别出退化：新版过度生成、形状还原变差，而不是一味认为「新的一定更好」
输入条件对照 单视图与多视图对比；简洁节点流程与复杂流程对比 混元的单视图生成比多视图更稳定；简洁的节点流程效果更好
参数扫描 同一模型分别设 4000 / 8000 / 10000 面，另测标准模式 超面是系统性偏差而非随机误差（见下一节）；标准模式不走智能拓扑，会直接保留高模坑洞与棱角，卡通规范不符

一个可量化的系统性偏差：超面率

把五次不同设置的结果放在一起，会看到一个很稳定的规律：

平台 设定面数 实际生成 超出比例
Meshy（智能 topo）80008807约 10.09%
Meshy（智能 topo）1000011081约 10.81%
Meshy（智能 topo）40004408约 10.2%
Tripo（四边面）1000011355约 13.55%
Tripo（四边面）50005539约 10.78%

五个样本、两个平台，超出比例稳定落在 10%～14% 区间，与设定值本身几乎无关。原始记录里的判断是「不管设置多少面，最后都会超出几百面。

这个结论对验收有直接意义：核面数时必须按实测面数，而不是按设定值签收。同时它也是个跨平台的系统性问题，不是某一家没做好——所以不能当成个案反馈，应当作为通用约束写进验收流程。

向视频生成延伸：哪些判据能迁移

上面四层是为三维网格建的，但其中大部分判据并不依赖「输出是不是网格」。角色比例、结构漂移、材质光照、风格一致性、资产还原这几项，注释对象从模型换成视频帧，判断逻辑基本不变。

真正新增的是时间维度：

新增维度 现象 与三维问题的对应关系
时序一致性 动作衔接断裂、肢体在相邻帧间跳变 相当于拓扑在时间上崩坏
镜头连续性 运镜跳切、机位无理由变化 相当于空间关系在镜头间不守恒
遮挡与交互 穿模、遮挡关系错乱、角色与环境互不作用 相当于部件边界与装配结构丢失
长时身份保持 同一个人物在中后段逐渐变形、服饰漂移 相当于跨部件的一致性失效
待实测 这一节目前是框架，不是结论。我在三维网格上做过的对照实验、量化统计和分档判定，在视频生成上还没有对应的实测数据。把它写在这里是为了说明判据的迁移路径是通的，而不是宣称已经测过。补上实测之后，这一节会换成和上面同规格的案例与数据。

一句话总结

评测不是「我觉得不行」，而是把「不行」拆成可以被别人复现、被工程师执行、被流程签收的东西：按层找问题（数据 / 形体 / 表现 / 任务），按档给结论（可用 / 可修复 / 不可用），按四要素写描述（位置 / 现象 / 量级 / 归因），用对照实验证明它是稳定偏差而不是偶发。

这套口径最初是为三维资产生成的验收写的，但它的骨架与具体模型无关——换一个生成模态，只需要换掉判据清单，判定流程不用重建。
