项目废案合集

集中记录中途暂停或不继续推进的项目，整理其背景、中止原因与留存经验，便于之后复盘与复用。

起始记录：2025年11月18日 持续更新中 分类：废案留存

一、合集说明

写在前面：不是所有项目都能从想法走到上线发布，有些因为时间限制、方向调整或外部原因中途暂停。把这些方案集中记录在这里，一方面避免首页开发日志里出现大量"半截项目"，另一方面也能把做过的取舍、踩过的坑和可复用的资产沉淀下来，之后有新想法再回来延续。

本合集收录的范围包括：

  • 因为时间、团队、外部条件限制中止的项目原型或参赛方案
  • 做了一部分但后续方向有变化、不再继续推进的独立尝试
  • 暂时搁置、有时间再回来延续的长期想法

废案一 · 多人音乐格斗对战（音乐类 3D 游戏原型）

1. 项目背景

该项目为 2025 年 CrazyWeb 开发比赛的参赛项目。最初的方向是一个大型3D音乐对战类游戏原型，节奏玩法 + 拳皇式多人对战的复合结构，美术风格原计划对标《罪恶装备》系列，追求偏华丽的视觉呈现与独特的角色语言。

我在团队中担任 3D 美术岗位，负责角色与场景的设计与制作；其他部分原定由队友分别承担策划撰写、玩法开发、音频处理等工作。

2. 技术栈

  • Unity 引擎
  • C# 脚本
  • 音频处理 / 节奏检测 / 音乐可视化
  • 风格化3D美术流程

3. 已完成的部分

  • 角色与场景的初始美术方向定调（对标《罪恶装备》的风格化思路）
  • 音乐系统雏形（音频加载播放、节奏检测、音效系统的初步结构）
  • 基础节奏玩法骨架（节奏点击、分数系统、难度调整、连击机制的初始实现）
  • 音乐可视化部分（频谱分析、粒子与灯光配合的初步效果）

4. 中止原因

核心问题出在策划案的体量与比赛周期不匹配。原策划目标定得过于宏大，叠加了 3D 对战、音乐节奏、多角色多关卡、多人对战等多条需求线，在短短几天的赛事周期里根本无法完成。随着时间推进，队伍对交付范围的共识越来越难达成，最终在中途解散，项目没有继续推进。

从结果回看，这类复合型项目如果参加短期比赛，更合理的做法是先锁死一小段可玩切片，再围绕这个切片反向收敛需求，而不是一开始就把多条玩法线同时铺开。

5. 留下的经验与可复用资产

  • 短期赛事里"定好可交付边界"远重于"把所有想做的东西都塞进去"
  • 节奏检测、音频频谱可视化的基础实现逻辑，之后做互动叙事或音画联动类项目可以直接复用
  • 风格化 3D 角色美术对标《罪恶装备》方向的初步探索经验，后续角色项目可沿用
  • 复合玩法（音乐 + 对战）拆分交付的思路，对之后的项目节奏判断很有帮助

6. 对标补记 · 关于《罪恶装备》系列的美术与布线方案

最近整理废案资料时又补了一轮《罪恶装备》的美术制作方法，尤其是社区最近重新讨论起来的"非标准布线思路"。这也是当初项目对标这个系列时我重点关注的方向之一——他们的模型与绑定方案，和国内常见项目组的做法有明显差异。

主流 3D 项目（尤其是国产项目）在角色布线阶段会优先考虑方便动作师绑定：尽量保持规整的四边面、关节环严格对齐、布线走向服务于拉伸形变，模型是"为了绑定而存在"。《罪恶装备》的思路则反过来——模型与布线的核心目标是优先服务美术最终画面效果。对于动作绑定需要的规整度，他们并不像主流项目那样执著，反而更看重卡线出来的边缘剪影、镜头里的造型张力，以及与卡通着色器的配合表现。

下面是最近看到的两张装备布线参考图，对比就能直观感受到差异：

装备布线参考一：卡线与走向不追求四边面规整度

装备布线参考二：绑定方案同样是"效果优先"的思路

从这两张参考图就能看出：他们的卡线走向、环的密度、边缘的处理都不会刻意迁就"动作师上手即绑"的需求，而是围绕最终渲染画面的美术表现力来做权衡。绑定也是相应地配套定制，而不是反过来让模型迁就绑定。

废案二 · 解密小说（Unity 交互式小说项目）

1. 项目背景

解密小说是基于 Unity 引擎开发的交互式小说项目，融合了解谜元素与互动叙事两种体验。目标是为玩家提供不同于传统小说的全新阅读感受，让玩家通过实际操作与选择来推进故事发展，在阅读过程中获得参与感与沉浸感。

项目定位为个人独立开发，2024年11月启动，后续暂停推进。通过这个项目，我深入学习了互动叙事的设计思路、谜题难度的平衡方法，以及 Unity 中 2D 界面与交互系统的实现方式。

2. 技术栈

  • Unity 引擎（场景管理、界面渲染与交互分发）
  • C# 编程语言（剧情控制、状态管理与交互回调）
  • UGUI 2D 界面设计（对话框、物品栏、解谜界面、进度可视化）
  • 自建剧情分支状态机（记录玩家选择并影响后续节点走向）
  • 谜题设计（物品收集使用、密码破解、环境触发等多种解谜机制）

3. 已完成的部分

  • 分支剧情系统 支持多分叉剧情节点与不同结局路线，玩家选择会影响故事发展方向
  • 对话系统 角色台词逐字显示，说话者切换与气泡排版
  • 选择机制 关键节点提供多选按钮，选择结果写入剧情状态
  • 故事状态管理 集中管理已触发剧情、已解锁内容、已收集物品
  • 物品收集与使用 场景中拾取物品放入背包，在指定位置组合使用
  • 谜题解谜 拼图、顺序触发、图案匹配等多种形式
  • 密码破解 通过线索推理密码，解锁关键内容
  • 环境互动 场景中可点击的物件提供线索或推动剧情
  • 完整 UI 体系 对话界面、物品栏（背包展示/物品详情/拖拽使用）、解谜界面、故事进度跟踪

4. 暂停原因

项目在完成核心框架后暂停推进。主要原因是个人精力转向其他项目，加上互动叙事项目的内容体量（剧情文本量、谜题关卡数量、分支路线复杂度）远超预期，独立开发下难以在短期内补齐全部内容资产。框架和系统已经跑通，后续有时间可以从当前节点继续延展。

5. 留下的经验与可复用资产

  • 互动叙事是非常有力的游戏设计工具，能在低成本下创造引人入胜的体验
  • 谜题设计需要平衡挑战性与趣味性，最好预留多级提示或软失败机制
  • Unity 的 UGUI + 状态机组合足以支撑中轻度的互动叙事项目
  • 集中式的故事状态管理对于分支叙事至关重要，分散管理会很快失控
  • 界面排版节奏、台词显示速度直接影响故事的沉浸感受
  • 自建的剧情分支状态机框架，后续叙事类项目可以直接复用

复盘补充：互动叙事项目中，谜题难度曲线与剧情节奏要一起规划，过难过易都会打断故事的沉浸感。这个项目的框架虽然跑通了，但内容量才是决定这类项目能否完成的关键因素——技术不是瓶颈，内容资产才是。

废案三 · AI短剧创作尝试（用AI弥补剧情遗憾）

1. 项目背景

2026年7月，开始尝试用AI工具制作短电影，主要是为了弥补一些喜欢的作品剧情太少、意犹未尽的遗憾。很多时候看完一部动画、游戏或者小说，总会觉得某些情节没有展开，某些角色的故事线不够完整，于是萌生了用AI来创作属于自己的续作或番外的想法。

AI技术的发展让个人创作者也能实现电影级别的视觉效果，无需庞大的团队和高昂的成本。通过AI生成画面、配音、配乐等元素，可以快速将脑海中的故事呈现出来，对于表达个人创意和情感是一种非常有效的方式。

2. 制作流程

  • 构思剧本 根据喜欢的作品设定，构思新的剧情线或番外故事，确定角色、场景和情节发展
  • 生成分镜 使用AI工具根据剧本描述生成关键帧画面，确定镜头角度和画面构图
  • 画面生成 基于分镜描述，使用AI图像生成工具生成逐帧画面
  • 后期合成 将生成的画面导入视频编辑软件，添加转场效果、字幕和背景音乐
  • 配音与音效 使用AI配音工具为角色添加语音，配合音效增强沉浸感

3. 已完成的部分

  • 为喜欢的游戏角色创作独立故事，展现他们在主线剧情之外的生活片段
  • 跑通了"剧本构思 → AI分镜生成 → 逐帧画面生成 → 后期合成 → AI配音音效"的完整制作流程
  • 在毕设项目中实际应用了AI配音与音效生成（字节的音效工具），毕业展期间观众反馈不错

4. 暂停原因

项目在完成流程验证与部分创作后暂停推进，核心问题集中在AI生成内容的技术瓶颈上。画面一致性方面，AI生成的画面在不同帧之间存在风格不一致的问题，需要反复调整提示词；动作连贯性方面，生成的连续帧之间动作衔接不够自然，需要大量后期手动调整；配音情感表达不够细腻，难以支撑完整的叙事需求。叠加短剧时长有限、叙事节奏把控难度大的问题，独立创作下难以在可接受的成本内产出满意的作品。

5. 留下的经验与可复用资产

  • AI图像生成、AI视频生成、AI配音的完整工作流程已跑通，后续类似创作可以直接复用
  • 画面一致性是当前AI视频创作最大的技术门槛，提示词工程只能缓解、无法根治
  • AI配音工具（字节的音效）可用于毕设级别的项目交付，但情感表达仍需人工把关
  • 短剧叙事的核心难点在于"短时间讲好完整故事"，与工具无关，是剧本层面的能力

复盘补充：这个尝试虽然是废案，但验证了AI工具链在个人创作中的可行性与边界。技术瓶颈（画面一致性、动作连贯性）会随着AI工具迭代逐步缓解，到时候可以捡起来继续。
