人机交互开发日志：用声音和手来控制

语音驱动角色 + 摄像头手势识别 · 交互研究记录

发布日期：2026年11月15日 | 分类：人机交互 / Web 前端 / 实时音视频 | 方向：语音输入 · 手势交互 · 界面联动

想做的东西

键鼠和触屏之外，还有两种很自然的输入：声音和手。这次想验证两条链路。

  • 用声音大小驱动游戏角色，类似王者荣耀里朵莉亚那种用喊声控制技能强度的玩法。早前在手机上做传声筒时，是通过麦克风接口读输入电平来判断喊得多大声，思路可以沿用。
  • 用摄像头识别手，手掌和手指的位置能推动界面上下移动，手停在某个交互点上就能触发页面上的动态交互。

两条链路最终要落到同一件事：把人体信号变成稳定、可预期的输入事件。

语音链路：从麦克风电平到角色行为

先拆开看，声音输入其实只有三件事：采集、量化、映射。

环节做法产出
采集 getUserMedia({ audio: true }) 拿到音轨，接进 AudioContext，经 AnalyserNode 取时域波形 每帧一串 0 到 255 的采样值
量化 对波形求 RMS，再做包络平滑（起音快、释放慢），滤掉单帧抖动 一个稳定的 0 到 1 音量值
映射 按阈值分段，映射成技能蓄力、持续施法、打断三种状态 角色行为与 UI 反馈

量化这一步决定了手感。直接用瞬时音量会让技能条疯狂抖动，所以要做包络跟随：声音变大时快速跟上，声音变小时缓慢回落，视觉上才像在蓄力，而不是在闪烁。

映射层的设计

  • 阈值分段：轻喊进入预备态，中等音量持续蓄力，超过高阈值直接释放。
  • 滞回：上升和下降用不同的阈值，避免在临界点上反复触发。
  • 上限约束：音量持续拉满要封顶，否则麦克风爆音会一瞬间打满整条技能条。

语音链路的坑

  • 浏览器的自动增益：默认开启的 autoGainControl 会把小声拉大、大声压小，音量曲线被抹平，必须显式关掉；echoCancellation 和 noiseSuppression 同样会削掉一部分有效信号，按用途决定。
  • 底噪：安静房间也有电流声，阈值不能写死，需要开局先采集一小段静音算出底噪基线。
  • 授权时机：麦克风权限必须由用户手势触发，页面加载时直接申请会被浏览器拦掉。
  • 设备差异：不同麦克风的灵敏度和频响差别很大，同一套阈值在手机上能用、在笔记本上就失灵，所以阈值要跟着基线走。
  • 延迟：从发声到画面响应有几十毫秒的感知延迟，UI 上要用即时的波形或音量条先把反馈给出去。

校准流程：静音采样一秒取底噪，再让用户持续发声两秒取峰值，两者之间插值出低中高三档阈值。一次校准就能适配大部分设备。

手势链路：摄像头到界面

摄像头这条路，用的是手部关键点检测：从视频帧里回归出手的 21 个关键点，包括手腕、五根手指的每个关节和指尖。拿到坐标之后，剩下的事就是纯前端的坐标映射与命中判定。

步骤做法注意点
取帧 摄像头视频流喂给推理模型，逐帧检测 分辨率不用高，降采样反而更稳更快
取点 食指指尖与掌心作为两个控制点 指尖适合指向，掌心适合整体拖动
映射 归一化坐标乘上视口宽高，水平方向做镜像 不做镜像会左右反向，操作立刻别扭
平滑 指数滑动平均或单欧元滤波，抑制手抖 平滑太强会拖影，太弱会抖，要按场景调
命中 指尖坐标换算成页面坐标，做悬停与捏合判定 捏合比点击更自然，阈值要按手的尺寸做归一化

交互手势

  • 悬停：指尖落在交互点上，元素放大、发光，表示可以触发。
  • 捏合：拇指与食指距离小于一个相对阈值，判定为点击。
  • 上下推移：掌心纵向位移映射成页面滚动，位移速度控制滚动速度，抬手即停。
  • 停留触发：指尖在交互点上停留固定时长，用于不方便捏合的场景。

手势链路的坑

  • 抖动与误触：原始关键点每秒都在小幅跳动，不做平滑会把界面点得一片乱。
  • 光照与遮挡：逆光、手部出画、手指交叉，都会让关键点瞬间丢失，需要做丢帧保持而不是立刻判定抬手。
  • 缩放不一致：手离镜头远近会改变掌心尺寸，所有距离阈值都要用掌宽做归一化，不能写死像素。
  • 性能：推理跑在主线程会卡住动画，要按帧率节流，或者放到 Worker 与离屏渲染里。
  • 隐私：视频帧只在本地推理，不上传服务器，页面上明确提示摄像头已开启并随时可以关闭。

两条链路怎么合起来

声音和手势不是并列的两个功能，而是一套统一的输入状态机：

  • 手势负责指向与选择，决定现在关注哪个对象；
  • 声音负责强度与施放，决定对这个对象做多大力度的操作；
  • 两者都退出时回到空闲态，界面收回悬停反馈。

状态机的好处是所有输入最终都收敛成有限的几个状态，调试时能一眼看出卡在哪一步，而不是在回调里互相打架。

阶段小结

语音那条链路的难点不在采集，而在量化和映射：把连续的音量变成离散又稳定的技能状态，手感才立得住。手势那条链路的难点不在识别，而在平滑与命中判定：模型给出的坐标是准确的，但人手本身在抖，交互的容错要由界面层兜住。

这两条链路后续还可以继续往下做：声音做频谱而不是只有音量，识别音高与音色；手势从单手 21 点扩到双手与姿态，做抓取、旋转这类更复杂的手势。等实测素材整理出来，再把具体的调参记录和数据补进这一篇。
