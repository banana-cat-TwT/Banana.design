GPT3D AI Asset Pipeline 开发日志

2026年10月 · 工具开发 · AI 3D PBR 资产自动生成流水线

AI 3D 资产管线 PBR 自动化 Blender Tripo Meshy OiiOii

项目定位

GPT3D AI Asset Pipeline 是一套跑在本地 Windows 环境里的 AI 3D PBR 资产自动生成流水线。目标是把「文字或图片输入」到「可用 3D 资产输出」整条链路串起来，减少在生图平台、3D 生成平台、Blender 之间来回手动操作。

这套工具不追求「一键生成完美模型」，而是把重复性强的搬砖动作收进一条可复用的管线，让批量 3D 资产生产能稳定地产出、可追溯地记录每一步。

要解决的问题

过去做一件 3D PBR 资产，得先在生图平台出概念图，再手动传到 Tripo、Meshy 或混元 3D 生成网格，再下载、导入 Blender、绑材质、导出。多个网页来回切，重复劳动多，还容易漏步骤、丢记录。

GPT3D 把这些步骤收成一条管线，每一段都有明确的输入、动作、交付物，出问题能定位到具体环节，而不是在几个平台之间来回猜。

整体架构

管线分四段，从上游到下游依次是输入、2D 概念图、3D 生成、处理与导出。

阶段做什么工具或平台说明
第一段 输入接收文字提示词或参考图片本地项目配置每次任务都从这里开始
第二段 2D 概念图自动生成并下载概念图OiiOii（官方 CLI）复用已有会员，命令行接入
第三段 3D 生成文字或图片转网格模型Tripo、Meshy、混元 3D统一 API 适配层，Tripo 优先
第四段 处理与导出导入、绑材质、导出Blender 5.2 Python APIPBR 整理与 FBX、GLB、USD 导出

第三段的三个 3D 平台通过一个 统一 API 适配层 接入，对外暴露同一套接口。默认走 Tripo，失败或需要多平台对比时切换到 Meshy 或混元 3D，上层调度逻辑不用感知平台差异。

技术选型与运行环境

运行环境是 Windows 11，显卡 NVIDIA RTX 5080，内存 32GB，Blender 5.2。

模块选型说明
2D 生图OiiOii已有会员，通过 @oiioii/cli 命令行接入
3D 生成Tripo、Meshy、混元 3D云端 API，Tripo 优先
任务调度Python状态轮询、下载、异常重试
本地记录SQLite任务状态与历史可追溯
模型处理Blender 5.2 Python API导入、PBR 绑定、导出

API Key 只存在本地环境变量或加密配置里，不写进代码库、不提交到版本管理。

早期的 2D 生图方案想过复用 E 盘已有的 ComfyUI 安装，但考虑到已有 OiiOii 会员、且命令行接入更直接，最终优先走 OiiOii，ComfyUI 作为备选保留。

目录结构与输出规范

本地目录按职责拆分，系统与启动脚本、全局配置与 API Key 存储、管线主代码、资产生成结果、临时文件、备份、运行日志各自独立，互不干扰。

每个资产一个独立项目目录，统一生成分类子目录和 project.json、manifest.json、README.txt、generation.log 等记录文件，保证每一步都有据可查。

PBR 贴图按 Base Color、Roughness、Metallic、Normal、AO 五类整理，并检查色彩空间，Base Color 用 sRGB，数据贴图用 Non-Color。

分阶段实施

整体拆成五个阶段，每个阶段单独验证通过后再进下一步。

  • 第一阶段 建立本地运行环境，把目录骨架、配置文件、依赖安装跑通。
  • 第二阶段 做 2D 生成模块，接入 OiiOii CLI，验证文字和图片生成概念图。
  • 第三阶段 接入三个 3D 平台，先跑通 Tripo，再补 Meshy 和混元 3D。
  • 第四阶段 做 Blender 自动化，导入、绑 PBR、保存工程、导出多格式。
  • 第五阶段 搭本地 Web 工作台，把任务提交、进度、历史可视化出来。

当前进度与下一步

目前处于 规划和环境搭建阶段，已经确定整体架构与目录规范，ComfyUI 复用 E 盘已有安装，2D 生图优先接 OiiOii。

下一步按顺序推进，先安装 OiiOii CLI 并验证账号与图片生成权限，然后接 Tripo API 完成第一件端到端的模型，把整条链路跑通一次后再扩展平台和自动化。
