2D 游戏角色骨骼绑定与动画

2026年5月12日 分类：动画制作
制作软件：Spine（Esoteric Software）
制作内容：2D 游戏角色骨骼绑定与动画、场景动态骨骼绑定
使用时段：2023年6月起，短期间断使用，后转3D停止
记录日期：2026年5月12日

一、项目概述

2023年6月开始接触 Spine，源于当时想要组队做游戏的契机。在网上寻找组队伙伴时，遇到的第一个程序说需要会Spine的人——当时完全不知道Spine是什么，于是自己搜索软件和教程，开始自学并尝试为OC角色绑定骨骼动画。期间完成了角色绑骨并使其动起来，同时尝试了场景动态的骨骼绑定——即为场景元素也添加骨骼驱动以实现动态效果。后因转向3D工作流，Spine 使用随之停止。

组队经历：最初找到一个团队计划做海洋主题的模拟经营游戏，只出了策划草案和场景草案，拉了飞书群后就没有后续了。这次经历让我意识到：能遇到能一直合作下去的队友有一定的风险性——大部分队友做着做着就不做了，要么策划之间吵架，要么策划规划不切实际导致其他职能与策划产生矛盾，要么策划出了草案就没下文了。大一下遇到的队友大多如此，这也为以后找队友打下了一定的心理预期。

与 Live2D 的定位区别：Live2D 偏向虚拟主播/立绘动态展示，参数驱动+表情系统为主；Spine 偏向2D游戏动画，帧动画+骨骼动画为主，更强调游戏内的实时动作表现。

时间事件

3.2 前期准备——2D素材拆分

与 Live2D 类似，Spine 也需要将完整角色立绘拆分为独立部件图层：

拆分对象拆分要点
角色按关节拆分（头、躯干、上臂、前臂、手、大腿、小腿、脚），每个可动部分单独图层
场景元素需要做动态的场景部分（如飘动的旗帜、摆动的树枝、流动的水面等）单独拆出
被遮挡区域同样需要补全被遮挡部分，避免运动时穿帮

Spine vs Live2D 拆分差异：Spine 更侧重按关节切分，强调部件之间的旋转连接关系；Live2D 更侧重按表情/功能部件切分，强调形变与参数映射。

3.3 骨骼绑定（绑骨）

角色骨骼绑定流程

  1. 导入素材：将拆分好的 PSD/PNG 序列导入 Spine
  2. 创建骨骼：在骨骼模式（Setup Mode）下创建骨骼层级
  3. 绑定图片：将各部件图片挂载到对应骨骼上
  4. 设置 IK 约束：为腿部/手臂添加 IK（反向动力学），简化动画制作
  5. 调整骨骼层级：确保父子关系正确（如前臂骨骼是上臂骨骼的子级）

角色骨骼参考结构

Root（根骨骼）
├── Hip（臀部）
│   ├── Spine（脊柱）
│   │   ├── Chest（胸部）
│   │   │   ├── Neck（脖子）
│   │   │   │   └── Head（头部）
│   │   │   ├── L_UpperArm（左上臂）
│   │   │   │   ├── L_Forearm（左前臂）
│   │   │   │   │   └── L_Hand（左手）
│   │   │   └── R_UpperArm（右上臂）

场景骨骼绑定

除角色外，也为场景元素添加骨骼以实现动态效果：

场景元素绑骨方式动态效果
旗帜/布料沿长度方向添加多节骨骼随风飘动
树枝/藤蔓从根部到末端逐级添加子骨骼摆动、弯曲
水面/波浪横向排列骨骼，交替设置动画波纹流动
灯笼/吊饰顶部单点骨骼 + 物理约束随风摇晃

场景绑骨是 Spine 的一个特色应用方向——不仅仅用于角色，任何需要2D动态表现的对象都可以通过骨骼驱动实现。

3.4 网格变形（Mesh Deformation）

Professional 版支持对图片添加网格并进行顶点变形：

功能说明
网格编辑为图片添加可变形的三角形网格
顶点权重绑定将网格顶点绑定到多根骨骼，实现平滑过渡变形
应用场景角色呼吸时胸部起伏、布料飘动、肌肉形变等

3.5 动画制作

Spine 以关键帧动画为核心：

动画类型说明
骨骼动画对骨骼的位移/旋转/缩放设置关键帧
网格变形动画对网格顶点位置设置关键帧（需 Pro 版）
IK 动画通过 IK 约束简化肢体动画
事件动画在时间轴上触发音效/特效等自定义事件

常见游戏角色动画列表

动画名用途
Idle（待机）角色站立时的微动循环
Walk / Run（走/跑）移动循环动画
Attack（攻击）普攻/技能动作
Hurt（受击）被攻击时的反馈
Die（死亡）倒地/消散动画

3.6 导出与接入游戏引擎

导出格式用途
.json + .atlas + PNG数据文件+图集，用于运行时加载
.skel（二进制）更小的文件体积，用于正式发布
视频/GIF预览和展示用

导出后通过对应运行时（如 Spine-Unity Runtime）接入游戏引擎即可使用。

五、注意事项与经验总结

要点说明
骨骼层级是核心父子关系必须正确，否则动画会出现连锁错误
IK 约束大幅提效手臂/腿部的 IK 约束能极大简化行走/攻击等动画的制作
场景绑骨同样重要好的2D游戏场景动态往往靠 Spine 骨骼驱动，而非逐帧手绘
Pro 版功能差异大网格变形是 Pro 版独占，没有它很多平滑形变效果无法实现
拆分需考虑动画需求同一个角色，不同动画需求下的拆分粒度不同，需提前规划
与 Live2D 定位不同Spine 面向游戏动画，强调帧动画+骨骼；Live2D 面向虚拟主播，强调参数+表情

六、与 Live2D 对比

维度SpineLive2D
