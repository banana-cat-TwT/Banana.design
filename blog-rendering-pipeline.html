实时渲染管线研究日志（图形学 · 面试题库）

2026年11月 · 技术整理 · 从 BRDF 到光追的工程取舍

微表面 BRDF Forward / Deferred 全局光照 阴影走样 后处理 光线追踪

先交代这一篇的位置

前面那篇 AI 3D 大模型研究日志 解决的是「资产怎么被生成出来、生成得对不对」；这一篇解决的是另一个问题——资产进引擎之后，怎么被正确地、划算地画到屏幕上。两件事的评判标准完全不同：前者看几何和材质数据本身干不干净，后者看画面结果和每帧预算。

这一套题集中在实时渲染管线，是技术美术、渲染向客户端、引擎工具这几个岗位的公共底座。我按同一个口径来答每一题：

  • 一句话定义：先能用一句话说清它是什么，证明概念没糊；
  • 物理 / 数学意义：公式里每一项到底在补偿什么现实，而不是背符号；
  • 工程取舍：什么条件下用它、什么条件下换成别的；
  • 踩坑点：真做项目时会在哪里翻车。

之所以要「取舍」这一层，是因为渲染没有标准答案，只有预算分配。同一个画面，PC 上可以硬追光线，手机上只能预烘焙 + 探针；说得出为什么，才算真懂。

微表面模型：GGX、几何遮蔽与菲涅尔

先给定义：微表面模型（Microfacet Model）把粗糙表面看成无数个朝向各异的微小完美镜面，用统计分布描述这些微面朝向，最后对它们积分，得到一个只靠「粗糙度」一个参数就能解释从镜面到粗糙漫反射连续变化的 BRDF。它的意义在于——真实材质表面在微观上本来就不平，微表面模型是把「不平」这件事数学化的标准做法。

Cook-Torrance 的完整形式

实时渲染里最常用的是 Cook-Torrance 形式，把 BRDF 拆成漫反射 + 镜面两部分：

f_r = k_d · (c / π) + k_s · [ D(h) · G(l,v,h) · F(v,h) ] / [ 4 · (n·l) · (n·v) ]

其中 D 是法线分布函数（NDF），G 是几何遮蔽函数，F 是菲涅尔项。这三项分别回答三个独立的问题：微面朝向怎么分布、微面之间怎么互相挡住、镜面反射率随角度怎么变。少任何一项，画面都会出问题。

三项各自在补偿什么

项物理意义常用形式删掉 / 写错之后的症状
D（NDF，GGX） 微表面法线朝向半角向量 h 的概率密度，决定高光的宽度、形状和拖尾 D = α² / (π · ((n·h)²(α²−1)+1)²) 高光变成均匀一团、没有锐利核心和外圈衰减，塑料感消失
G（几何遮蔽） 微面之间的相互遮挡与投影（masking & shadowing），能量在掠射角下的补偿 Smith + Schlick-GGX：G1(x) = (n·x) / ((n·x)(1−k)+k)，k=(α+1)²/8 掠射角边缘异常发亮、能量不守恒，边缘出现一圈「亮边」
F（菲涅尔） 反射率随观察角度变化：正对看是 F0，掠射角趋近 1 Schlick：F = F0 + (1−F0)(1−v·h)⁵ 没有边缘反光，所有材质像贴纸；地面、水面失去「越平视越亮」的感觉

三个最容易答错的点

第一，roughness 不等于 α。业界普遍做了一次 remap：α = roughness²（Unity、UE 及多数 PBR 管线都这么干）。如果直接把美术给的 roughness 当 α 用，中间粗糙度区间的高光会异常宽、看着像被磨砂糊住。这一题如果能主动说出这层 remap，基本就区分出「背过公式」和「真调过材质」。

第二，分母 4(n·l)(n·v) 不是归一化系数。它是从微表面分布到宏观 BRDF 的立体角变换雅可比。写成「除以 4 是为了归一化」是常见错误答案。

第三，F0 不是 0。非金属的 F0 约 0.04（常见近似），金属的 F0 直接用基色 albedo。而 k_s = F、k_d = (1−F)(1−metallic) 才是能量守恒写法——金属没有漫反射正是这条式子推出来的，不是单独规定。GGX 的 D 有一条很长的尾巴，这既是真实高光的来源（金属反光有拖尾），也是画面出现 fireflies 亮点的来源，所以它和后面要讲的降噪、TAA 是连着的问题。

工程上最常见的事故不是公式写错，而是贴图色彩空间错了：roughness / metallic / AO 是数据贴图，必须按线性（Linear / Non-Color / sRGB 关闭）采样；albedo 才是 sRGB。这一条错了，整批材质会「看起来都差一点」，而且怎么调参数都调不回来。

渲染路径选型：Forward、Deferred 与 Forward+

三者的差别只有一句话：光照计算发生在几何着色的那一次 pass 里，还是拆成「先写几何信息、再算光照」两步，以及光源列表是全局给还是按屏幕分块给。

维度Forward（前向）Deferred（延迟）Forward+（分块前向）
基本做法 逐物体、逐光源，直接在着色 pass 里算完光照 先写 G-Buffer（albedo / normal / roughness+metallic / depth），再全屏逐光源算光照 先按屏幕 tile（或 3D cluster）剔除出影响该块的光源表，forward pass 只遍历这张表
光源扩展性 差。光源越多，着色重复越多、shader 变体越爆 好。光照成本 ≈ 屏幕像素 × 光源覆盖，与几何复杂度基本解耦 较好。接近 deferred 的可扩展性，但有上限
带宽 低 高。G-Buffer 多张 RT 写出再读回，移动端 TBDR 上极不友好 中。需要一次光源列表构建（compute）
MSAA 原生支持 不友好，通常要靠 TAA / 超采样代替 原生支持
透明与半透 天然支持 不支持，必须另开 forward 通道补 天然支持
材质灵活性 高。每个材质可以写自己的光照模型（NPR、次表面、布料到头发） 低。G-Buffer 参数集固定，特殊材质要额外通道 高
典型场景 移动端、VR（必须 MSAA）、光源少、风格化 / 卡通渲染 PC / 主机 3A、大量动态光源、强依赖屏幕空间效果（SSAO / SSR / SSGI） 移动 / VR + 多光源、URP Forward+、需要 MSAA 又要光源数量撑住

为什么移动端几乎不用 Deferred

因为移动 GPU（PowerVR / Mali / Adreno）是 TBDR（Tile-Based Deferred Rendering）架构：把屏幕切成小块，在片上 tile memory 里完成着色，尽量不写系统内存。Deferred 的 G-Buffer 恰恰要求把多张大 RT 写出去再读回来，带宽直接被击穿，还会连带破坏 TBDR 的「深度预通道 + 隐藏面剔除」优势。所以移动端要么 forward，要么 Vulkan subpass 里做片上 deferred，要么就走 Forward+ / cluster。

Forward+ 到底「+」在哪

它不是新的着色模型，而是光照剔除策略的升级：传统 forward 每个物体都要遍历场景全部光源，Forward+ 先用 compute 把屏幕划成 tile（典型 16×16）或 3D cluster，算出「哪些光源真的照到这一块」，生成 light index 列表，forward pass 里只查这张表。这样既保留了 forward 的 MSAA、透明、材质自由，又把「光源数量」这个最痛的扩展性问题解决掉了大半。

代价是：光源列表要每帧重建；光源大量重叠、或单个光源影响范围极大的场景下收益会掉；复杂反射/多层透明依旧不如 deferred 好用。

面试时说选型的正确姿势不是「Deferred 更先进」，而是先说平台约束、再说光源规模、再说是否需要 MSAA 和透明、最后才落到方案。真实工程几乎都是混合：UE 默认 deferred，但透明和特殊材质走 forward 通道；移动端 forward+，靠 depth prepass 压 overdraw。

全局光照：从烘焙到实时光追

全局光照（GI）指的是除了直接从光源打到表面的光之外，所有经过一次以上弹射才到达表面的光——包括漫反射互反射、镜面反射互相映照、以及由遮挡产生的间接明暗关系。实时渲染追求的是渲染方程的一个可算近似：

L_o(x, ω_o) = L_e(x) + ∫_Ω f_r(x, ω_i, ω_o) · L_i(x, ω_i) · (n·ω_i) dω_i

直接光只算了 L_i 里来自光源的那一小块；GI 要补的是 L_i 里「其他表面反射过来的光」。难点在于这个积分要对整个半球做递归，实时根本算不完，所以所有实时方案都是在「怎么用最便宜的方式近似这个积分」上做文章。

方法原理动态性主要缺陷
光照贴图 Lightmap 离线烘焙每个纹素的间接光，运行时只采样 静态。光照或几何一变就得重烘 占显存/UV 第二套；动态物体完全用不了
光照探针 Light Probe 用球谐（SH，通常 L2 共 9 系数）在空间稀疏点存低频间接光，动态物体就近插值 支持光照渐变、时间变化 只能表达低频；插值泄漏（隔墙互相串光）、接触处没有遮挡细节
反射探针 Reflection Probe 预捕获 cubemap，运行时按粗糙度选 mip 做反射；Box Projection 修正视差 静态捕获，可做局部更新 反射内容不会随场景动态变化；接缝和视差错误
Voxel GI 把场景体素化，运行时用 cone tracing 采样体素，近似多次弹射的漫反射与遮挡 支持光照变化，几何变化需重建 体素分辨率决定精度，薄结构必漏光；内存大
SDFGI 运行时构建多级 signed distance field（clipmap），ray march 求间接光，支持多弹射 高。动态几何可自动重建 构建有开销；SDF 表达不了薄面与细节 → 漏光、细节处发灰
SSGI（屏幕空间） 只用已渲染的深度/法线/颜色做屏幕空间 ray march 完全动态 屏幕外、被遮挡背面的信息不存在 → 信息缺失、边缘拖拽色带
RTGI / DDGI 硬件光追真实发射光线求交；DDGI 用探针 + 光线 + 时域累积更新球谐 完全动态 成本高、必须降噪；DDGI 有探针滞后与泄漏
Lumen 类混合方案 屏幕空间 trace + 表面缓存 / 距离场场景 + 可选硬件光追，多弹射近似 高 复杂、内存占用大；极端场景仍会漏光

评估一套 GI 方案，看五个指标

  • 动态性：光源变不变、几何动不动。这一条直接砍掉一大半方案。
  • 弹射次数：一次弹射只解决「物体侧面有环境色」，多次弹射才有封闭空间里的自然衰减。
  • 漏光：几乎所有实时 GI 的通病，越依赖低频表示（探针、SDF、体素）越严重。
  • 性能与稳定性：不只是平均帧率，还有帧时间抖动。
  • 内存：体素和探针方案经常是内存先爆，而不是先掉帧。

一句话的选型口径：全静态 → 烘焙最划算；有动态物体 → 静态烘焙 + 探针；光照会变 → 体素 / SDFGI；高端平台要真实感 → 硬件光追 + 降噪。

阴影贴图：走样从哪来，怎么治

Shadow Map 的原理一句话：从光源视角渲染一张深度图，再从相机视角把像素投影回这张图，比较深度判断是否被遮挡。问题在于——这张图是「用光源视角的均匀网格去表示相机视角看到的画面」，两个视角的采样密度天然不匹配，于是产生走样。

四类走样，成因不同，药也不同

走样类型成因表现
透视走样 阴影图在光源空间均匀分配纹素，相机视角下近处/远处投影密度差异巨大 远处阴影边缘粗、近处细；大范围场景分辨率永远不够
投影走样 表面与光线方向夹角大，一个纹素斜着贴到表面上被拉长 斜面上出现阶梯状锯齿
自阴影走样（acne） 纹素内深度被当成常数，表面与自身深度比较时误判为被遮挡 表面出现条纹状斑纹
闪烁 / 滑动（shimmering） 相机或光源移动时，阴影图纹素网格相对场景滑动 阴影边缘持续爬行、抖动，静止时也不安分

对应解法

技术治什么代价 / 副作用
提高分辨率 + 收紧投影范围 透视走样 显存与渲染开销线性上升，只能缓解不能根治
CSM 级联阴影 透视走样 把视锥按距离切 3–4 级，每级单独正交投影，近处精度高。级联之间需要 blend band 过渡，否则能看到接缝
纹素网格对齐（texel snapping） 闪烁 / 滑动 把投影中心按纹素尺寸取整，牺牲一点精度换稳定性。这一条最容易被漏掉，但它才是 CSM 能不能用的关键
Depth Bias / Normal Offset Bias 自阴影 acne bias 太小仍有斑纹，太大则阴影与物体脱离（peter-panning）。法线偏移比常深度偏移更不容易脱影，是更好的选择
PCF 百分比渐近滤波 硬边锯齿 在阴影图里做多次比较再取比例，用采样数换软边。半径固定，近处软远处更软，不物理
PCSS 软阴影 硬边 + 半影不物理 先 blocker search 求平均遮挡深度，再按相似三角形算半影宽度 w=(d_recv−d_block)/d_block · w_light，用这个宽度做 PCF。接触处硬、越远越软才物理正确，但开销是普通 PCF 的数倍，通常配低分辨率 + 时域累积
VSM / EVSM 硬边，且可预滤波 存深度的一二阶矩，可 mip 预滤波一次采样出软阴影。但漏光（light bleeding）明显，深度分布复杂时崩
虚拟阴影图（VSM / Virtual Shadow Map） 分辨率与走样的根本矛盾 按屏幕需求动态分配 page，等效分辨率远超单张图，配合缓存只更新变化区域。实现复杂、显存占用大
屏幕空间接触阴影 / 光追阴影 小尺度接触处的细节 补 shadow map 表达不了的接触暗部；光追阴影质量最高但成本也最高

这题想拿高分，关键是把「bias 只能治 acne，治不了走样」说清楚。很多人一遇到阴影问题就调 bias，结果斑纹没了、影子飞了，边缘锯齿一个没少。走样的根因是采样率不匹配，只有分辨率、级联、滤波这些手段能动它。

后处理管线：从 HDR 到屏幕

后处理管线指的是场景渲染完成之后，对整张图像做的一串全屏 pass，把 HDR 线性空间的结果转成能在显示器上正确显示的画面，并叠加上镜头与眼睛才会有的效果。它之所以必须存在，是因为渲染输出的数值范围远超显示器能表达的 0–1，且人眼/镜头本身有光学特性。

典型顺序

场景（HDR 线性） → SSAO / SSR → Bloom → 自动曝光 → Tone Mapping → 色彩分级（LUT） → 抗锯齿 / 锐化 → 景深、运动模糊、暗角、颗粒 → 输出编码（Linear → sRGB）

顺序本身就是知识点：Bloom 必须在 Tone Mapping 之前（要在 HDR 里取亮部，否则亮部已经被压成 1，全图一起发光）；曝光必须在 Tone Mapping 之前（曝光是调整 HDR 输入，色调映射是压缩到 LDR）；色彩分级在 Tone Mapping 之后（针对显示范围做创作性调整）。顺序错了，症状很典型，一测就能看出来。

四个必答特效的原理

特效原理关键约束
Bloom 泛光 把超过阈值（threshold + knee 平滑过渡）的亮部提取出来 → 多级降采样 + 模糊（mip chain / 双层滤波）→ 逐级上采样叠加 → 加回原图 必须在 HDR 与 Tone Mapping 之前；阈值定太高没有光晕，太低整个画面发雾
SSAO 屏幕空间环境光遮蔽 用深度重建视空间位置 + 法线，在半球内采样若干点，比较采样点深度与几何表面，统计被遮挡比例得到 AO 因子，乘到间接光/环境光上 只有屏幕内信息 → 屏幕边缘和屏幕外遮挡会丢失；有噪点需模糊或时域累积；本质是遮蔽近似不是真实 GI
TAA 时域抗锯齿 每帧给投影矩阵加亚像素抖动（Halton 序列），累积多帧历史；用 motion vector 把上一帧重投影到当前帧，做邻域 clamp / 方差裁剪后与当前帧混合 必须有 velocity buffer；clamp 太松出鬼影（ghosting），太紧又退化成单帧；快速运动下会拖影。它同时也是 SSR / SSGI / 光追降噪的时域基础
Tone Mapping 色调映射 把 HDR 值用一条 S 形曲线压进 [0,1]，同时尽量保持色相与感知对比。ACES 偏电影感、AgX 高光过渡自然且色彩保持好、Reinhard 最简单但容易发灰 不能简单 clamp（会死白、色彩断层）；通常配合自动曝光——按场景平均亮度（log 平均值或直方图）调整曝光，模拟人眼适应

顺带能把工程细节说出来会加分：中间 RT 应该是 float16 的 HDR 格式（LDR 格式存不下超过 1 的亮度，Bloom 直接失效）；全屏 pass 的采样要用双线性 + 尽量合并 pass（移动端每次全屏读写都是带宽）；低分辨率做 AO / Bloom / 光追，最后再合成。

光线追踪：降噪与混合渲染

光线追踪的定义：从相机（或光源）发射光线，与场景求交，命中点再按 BRDF 采样方向继续发射（或终止），最终累积得到像素颜色。它天然处理遮挡、软阴影、多次反射、折射和焦散——这些用光栅化要一个个 hack 出来，光追是直接算出来的。

实时化的两个真问题

第一是求交加速，靠 BVH（每个网格一棵 BLAS，场景级 TLAS 管实例）加硬件 fixed-function 遍历单元（DXR / Vulkan RT / Metal）。第二才是真正的难点：每像素只能发很少的样本，结果必然是噪的。路径追踪的方差跟样本数成反比，1 spp 的画面基本是雪花点。

降噪（Denoising）的三种路线

路线做法优点 / 风险
空间滤波 双边滤波、à-trous 小波（SVGF 一系）、guided filter：用深度 / 法线 / 材质作为 edge-stopping 函数，只在相似像素间平均 单帧可用；但边缘守不住就会糊掉细节，强滤波会出现「蜡像感」
时域累积 复用历史帧：重投影 + 方差估计 + 自适应混合权重，噪声在时间上平均掉 效率最高；但遮挡变化处必须靠 clamp 处理，否则出现拖影/鬼影
学习式 / 神经网络 NRD（ReBLUR / RELAX）、DLSS Ray Reconstruction 一类，用网络替代手工滤波 质量与稳定性明显更好，尤其薄结构和镜面；依赖特定硬件与模型，可控性下降

降噪器的输入端其实是同一份东西：G-Buffer（深度、法线、运动矢量）+ 材质参数 + 噪声颜色 + 样本数/方差。所以「降噪做不好」很多时候不是滤波算法的问题，而是运动矢量不准或材质 ID 缺失。

混合渲染（Hybrid Rendering）在混什么

核心思想：不用光追替换光栅化，而是让光栅化做它擅长的、光追只补它只有它能做的，并且光追部分一律降分辨率、配时域累积。

任务通常谁做混合策略
不透明几何、深度、法线 光栅化 光追只读这份 G-Buffer，不自己重新求交
直接光与主阴影 光栅化 + Shadow Map 只有接触细节或高质量需求才追加光追阴影
反射 SSR 优先 SSR 未命中 / 屏幕外时才发一条光追射线（fallback），避免为少数像素全屏开光追
漫反射 GI 探针 / 距离场 / 表面缓存 用低成本的场景表示做多次弹射，硬件光追只在需要精度时介入
透明、半透、毛发 光栅化 forward 光追对 alpha 与细分几何代价极高，继续走光栅

Lumen 就是这套思路的典型工程实现：屏幕空间 trace 拿近距离高频信息，表面缓存 + 距离场负责屏幕外和多次弹射，硬件光追作为可选加速。DDGI（动态漫反射 GI）也是同一逻辑——探针负责稀疏采样、光线负责更新探针、时域负责收敛。

这一题最容易被问的追问是「既然光追更准，为什么不全部用光追」。答案是预算和方差：全路径追踪要达到可用画质需要的样本数，远超当前实时预算；而光栅化在「确定的、大面积的、单次弹射」这件事上几乎没有浪费。混合渲染本质是把有限的 trace 预算花在观感收益最高的地方——反射、间接光、接触阴影。

面试口述速查

上面是完整版，这里是压缩到 3–5 句的口述版，面试被追问时按这个结构讲：

什么是微表面模型？D、G、F 分别管什么？
把粗糙表面看成无数朝向各异的微小镜面，用统计分布描述朝向，从而用一个粗糙度解释从镜面到漫反射的连续过渡，Cook-Torrance 形式是 f = kd·c/π + ks·D·G·F/(4(n·l)(n·v))。GGX 的 D 管微面朝向分布，决定高光宽度和拖尾；G 管微面之间的相互遮挡，补偿掠射角的能量；F 管反射率随角度变化，正对是 F0、掠射趋近 1。三项一起才保证能量守恒，其中 α 通常等于 roughness 的平方。
Forward、Deferred、Forward+ 怎么选？
Forward 一次 pass 算完光照，MSAA、透明、自定义光照模型都友好，但光源一多就爆炸；Deferred 先写 G-Buffer 再全屏算光照，光源扩展性最好，代价是带宽大、MSAA 和透明不友好、材质受限；Forward+ 是分块剔除光源的 forward，兼顾前者的灵活和后者的扩展性，代价是每帧要构建光源列表。移动端因为 TBDR 带宽限制，基本不用 deferred；PC 3A 用 deferred；VR 和移动多光源用 Forward+。
实时 GI 有哪些方法，怎么评估？
按动态性排：全静态用 lightmap；有动态物体用光照探针（球谐存低频）加反射探针；光照会变用体素 GI 或 SDFGI；屏幕空间 SSGI 便宜但屏幕外信息必然丢失；硬件光追 RTGI / DDGI 质量最高但要降噪。评估看五点：动态性、弹射次数、漏光程度、性能稳定性、内存。所有实时 GI 的共同缺陷是漏光，越依赖低频表示越严重。
Shadow Map 的走样怎么产生的，怎么优化？
根因是光源视角的均匀纹素网格和相机视角的采样密度不匹配，分透视走样、投影走样、自阴影 acne、以及移动时的闪烁四类。透视走样用提高分辨率、收紧投影范围、CSM 级联解决；闪烁必须靠把投影对齐到纹素网格；acne 靠 depth bias 或更好的 normal offset bias，但要小心 peter-panning；软边用 PCF，要物理半影就上 PCSS（blocker search 算半影宽度）；再往上就是虚拟阴影图或者光追阴影。注意 bias 只治 acne，治不了走样。
后处理管线是什么，Bloom / SSAO / TAA / Tone Mapping 原理？
是场景渲染完之后对整张图做的一串全屏 pass，把 HDR 结果转成正确显示的画面。顺序很关键：SSAO/SSR → Bloom → 曝光 → Tone Mapping → 色彩分级 → 抗锯齿。Bloom 在 HDR 里提亮部、多级模糊叠加，必须在色调映射前；SSAO 用深度重建位置、半球采样估遮挡比例，只有屏幕内信息；TAA 靠投影亚像素抖动 + motion vector 重投影历史帧 + 邻域 clamp 混合；Tone Mapping 用 S 曲线把 HDR 压进 0–1，配合自动曝光，绝不能直接 clamp。
光线追踪的降噪和混合渲染是什么？
光追是发光线求交，天然处理遮挡、反射、软阴影和 GI，求交靠 BVH 和硬件遍历单元加速。实时下真正的瓶颈是样本数不足带来的噪声，所以必须降噪：空间滤波（双边/à-trous，用深度法线守边缘）、时域累积（重投影 + clamp）、或学习式（NRD、DLSS RR），输入都是 G-Buffer + 材质 + 运动矢量。混合渲染是让光栅化做几何、直接光、透明，光追只补反射和间接光，并且 SSR 未命中才发光线、低分辨率 + 时域累积——本质是把有限的采样预算花在观感收益最高的地方。

小结

这六题串起来其实是一条完整的画面生成链：微表面模型决定一个像素的表面长什么样，渲染路径决定这些像素用什么方式组织计算，GI 和阴影决定光照关系对不对，后处理决定最后能不能正确地显示出来，光追与混合渲染则是把前四步里最难的部分用另一种算法补上。

回头看，所有答案的落点都不是「哪个技术更先进」，而是同一笔预算怎么分：分给分辨率还是分给光源数，分给烘焙还是分给实时，分给滤波还是分给采样。能把取舍讲清楚，比记住公式有用得多。
