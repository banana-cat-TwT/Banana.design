如何制作自己的Skill

Trae IDE技能开发完全指南

2026年5月7日 分类: 技术教程

什么是 Skill？

Skill 是 Trae IDE 中的扩展能力模块，本质是一份写给 AI 的 Markdown 指令文件。它不是传统意义上的插件代码，而是一套结构化的提示词，让 AI 在特定场景下按照你定义的流程去工作。

通过开发自己的 Skill，你可以：

  • 把重复的开发流程封装成一套可复用的指令
  • 让 AI 在特定任务中遵循固定的工作流和规范
  • 为团队共享一套统一的 AI 协作方式
  • 创建可独立运行的子代理（Agent 模式）处理专项任务

和传统插件最大的区别是：Skill 不需要写 JavaScript/TypeScript 代码，不需要 npm 依赖，也不需要打包发布——它就是一个文件夹 + 一个 Markdown 文件，写完即用。

Skill 的两种类型

Trae 的 Skill 分为两类，适用场景不同：

1. 普通 Skill（指令型）

最简单的形式，就是一份 Markdown 指令。AI 在对话中遇到匹配场景时加载这份指令，按照里面的步骤执行。适合封装固定流程，比如代码审查清单、提交规范、文件命名规则等。

2. Agent Skill（子代理型）

在 frontmatter 中声明 mode: agent，Skill 会作为一个独立的子代理（SubAgent）运行，拥有独立上下文、可限制工具权限、可挂载自定义工具。适合需要隔离执行环境的复杂任务，比如数据分析、API 查询、自动化测试等。

提示

刚开始接触建议先从普通 Skill 入手，熟悉结构后再尝试 Agent 模式。

开发前准备

1. 了解 Skill 的目录结构

一个标准的 Skill 就是一个文件夹，放在项目的 .trae/skills/ 目录下：

项目根目录/
└── .trae/
└── skills/
└── my-skill/ # Skill 文件夹（名字用 kebab-case）
├── SKILL.md # 核心指令文件（必需）
└── icon.png # 图标（可选）

2. SKILL.md 的基本结构

每个 Skill 只需要一个 SKILL.md 文件，由两部分组成：

  • YAML frontmatter（三横线包裹的头部）：定义 Skill 的名称、描述、模式等元信息
  • Markdown 正文：写给 AI 的详细指令，告诉它该做什么、怎么做

创建第一个 Skill

Step 1：创建目录

在你的项目根目录下创建 Skill 文件夹：

mkdir -p .trae/skills/code-reviewer

Step 2：编写 SKILL.md

在文件夹内创建 SKILL.md，写入 frontmatter 和指令正文：

---
name: "code-reviewer"
description: "Reviews code for best practices, bugs, and improvements. Invoke when user asks for code review or before merging changes."
user-invocable: true
---

# Code Reviewer

本技能用于对代码进行审查，输出结构化的改进建议。

## 工作流程

1. 读取用户指定的代码文件或代码片段
2. 从以下维度逐一检查：正确性、性能、可读性、安全性、代码风格
3. 对每个问题给出具体修改建议和示例代码
4. 按严重程度排序输出审查报告
5. 若审查范围不明确，先向用户确认重点关注的维度

Step 3：添加图标（可选）

在 Skill 文件夹内放一个 icon.png（也支持 jpg/svg/webp），Trae 会自动识别并显示为 Skill 的头像。

Step 4：使用 Skill

保存后无需任何编译或安装步骤。在 Trae 对话中：

  • 直接输入 /code-reviewer 即可手动调用
  • 当你的对话意图匹配 description 描述时，AI 也可能自动加载该 Skill
关键点

description 字段决定了 AI 何时调用这个 Skill，必须写清楚「做什么」+「何时调用」两部分，建议控制在 200 字符以内。

SKILL.md 字段详解

frontmatter 必填字段

  • name：Skill 的唯一标识，用 kebab-case（如 code-reviewer）
  • description：描述 Skill 的功能 + 触发条件。这是 AI 判断是否调用该 Skill 的依据，务必写清「做什么」和「何时调用」

frontmatter 可选字段

  • mode：设为 agent 则作为子代理运行；不填则为普通指令型 Skill
  • context：子代理的上下文策略，可选 isolated（默认，独立上下文）/ same_type / same_type_with_main / fork（继承全部对话历史）
  • allowed-tools：工具白名单，限定子代理只能使用列出的工具（如 Read、Edit、Grep 等）。不填则继承主代理的全部工具
  • user-invocable：设为 true 后用户可通过 /skill-name 手动调用。未设置时默认不可手动触发，只能由 AI 根据描述自动加载
  • disable-model-invocation：设为 true 禁止 AI 自动调用，只能手动触发
注意

allowed-tools 是白名单而非增量，一旦填写就只能在列表内使用。工具名拼错会静默失效，不确定时建议不填，让子代理继承主代理工具列表。

进阶：Agent 模式与自定义工具

创建 Agent Skill

把 mode 设为 agent，Skill 就会作为独立子代理运行，适合需要隔离执行环境的任务：

---
name: "data-analyst"
description: "数据分析子代理，擅长数据探索、趋势识别和脚本编写。当用户意图匹配该技能时，通过 Task 工具驱动该代理执行任务"
mode: agent
context: same_type
---

# Data Analyst

你是一名资深数据分析师，擅长统计分析、数据可视化与从原始数据中提炼可执行洞察。

## 工作流程

1. 接收用户的数据集或数据源引用
2. 探索数据结构，理解关键字段和分布
3. 识别与用户问题相关的趋势、异常和规律
4. 输出结构化分析摘要，包含关键发现和建议
5. 当分析目标不明确时，先用 AskUserQuestion 向用户澄清

挂载自定义工具

Agent Skill 可以挂载自定义工具（Shell 脚本），让 AI 能调用外部能力。结构如下：

.trae/skills/api-assistant/
├── SKILL.md
├── icon.png
└── tools/
└── query-user/
├── tool.yaml # 工具定义（名称、描述、参数）
└── run.sh # 执行脚本

tool.yaml 定义工具的参数 schema：

name: "query-user"
description: "通过用户ID或邮箱查询用户信息"
parameters:
type: object
properties:
user_id:
type: string
description: "用户ID"
email:
type: string
description: "用户邮箱"
required: []

run.sh 通过 stdin 接收 JSON 参数，通过 stdout 返回结果：

#!/bin/bash
TOOL_DIR="$(cd "$(dirname "$0")" && pwd)"

INPUT=$(cat)
USER_ID=$(echo "$INPUT" | jq -r '.user_id // empty')

if [ -n "$USER_ID" ]; then
curl -s "https://api.example.com/users/$USER_ID"
else
echo '{"error": "缺少 user_id"}' >&2
exit 1
fi

然后在 SKILL.md 的 frontmatter 中声明 custom-tools: ["query-user"]，AI 就能像调用原生工具一样调用它。

编写要点与避坑

1. description 是最重要的字段

AI 完全依赖 description 判断何时调用 Skill。必须同时写清楚「这个 Skill 做什么」和「什么场景下应该调用它」。写得太泛会导致误触发，写得太窄会导致该调用时不调用。

2. 正文要写成可执行的步骤

不要写概念介绍，直接写「工作流程：1. xxx 2. xxx 3. xxx」。AI 会按步骤执行，步骤越具体、越可操作，效果越好。

3. 用 kebab-case 命名

Skill 名和文件夹名都用 kebab-case（如 code-reviewer、api-assistant），不要用空格、中文或驼峰命名。

4. 自定义工具的子目录名必须和 tool.yaml 里的 name 完全一致

加载时会校验一致性，不一致会导致工具静默失效。

5. 语言保持统一

如果用中文写指令，整个 SKILL.md 就全用中文；用英文就全用英文，避免混用导致 AI 理解偏差。

总结

Trae 的 Skill 本质是「结构化的 AI 指令」，不是传统代码插件。开发一个 Skill 就是创建一个文件夹、写一个 SKILL.md，无需 npm、无需打包、无需发布流程。写完保存即可在对话中调用。

入门建议从普通指令型 Skill 开始，把日常重复的开发流程（代码审查、提交规范、命名规则等）封装成 Skill；熟悉后再尝试 Agent 模式和自定义工具，构建更复杂的自动化工作流。
