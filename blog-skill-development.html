引子 Skill 与赛博永生

最早想做这件事的动机可以用四个字概括 赛博永生。不是让 AI 替我活着，而是把思维方式、审美偏好、说话腔调、做决定的逻辑，从大脑里抽出来固化成一份机器能读能跑能替我在场的文件。

这件事在 WorkBuddy 里并不遥远，它有一个正式名字 Skill。系统甚至自带一份名为 自己.skill 的模板，专门用于把一个人蒸馏成可运行的 AI 分身，包含 Persona 与 Memory 两层。也就是说在我这套体系里，赛博永生本身就是一等公民功能，而非需要自己摸索的野路子。

全文顺着两条主线展开

  • 通用线 怎么在 WorkBuddy 里从零做一个普通 Skill，与 TRAE 教程一一对应
  • 永生线 怎么用 自己.skill 的思路，做一个会像你一样说话和思考的数字分身

一、什么是 Skill

Skill 是 WorkBuddy 的扩展能力模块。剥开包装，它本质就是一份写给 AI 的 Markdown 指令文件，由 YAML 元数据加 Markdown 正文组成，不是传统插件代码，不需要写 JS 或 TS，也不需要 npm 或打包流程。

封装重复流程

把每次都要手把手教 AI 一遍的固定步骤固化下来，例如代码审查清单、日报生成模板、提交规范说明。

统一协作口吻

让 AI 在固定场景中使用固定的标准、风格与口径回应，避免同一任务每次产出风格漂移。

创建数字分身

把你是谁、你怎么想、你怎么说话写进 Skill，AI 在触发条件命中时，就能以你的身份和腔调在场。

挂载工具资源

可以放脚本 scripts、参考文档 references、产出资源 assets，完成确定性更强且可复用的复杂任务。

与 TRAE 的对照

TRAE 的 Skill 同样是基于 SKILL.md 的结构化指令。WorkBuddy 与之高度同源，目录约定与 frontmatter 字段几乎一致，并额外支持 scripts、references、assets 三个资源目录与 .skill 打包分发。

二、Skill 的存放位置 两种作用域

作用域 路径 适用场景
用户级 推荐 ~/.workbuddy/skills/你的skill名/ 跨所有项目都可用，比如你自己的数字分身、个人代码审查规范。
项目级 工作区/.workbuddy/skills/你的skill名/ 只在某个仓库或项目内生效，适合团队协作规范与项目专属工作流。
对照 TRAE 的路径差异

TRAE 使用 .trae/skills 目录，WorkBuddy 使用 .workbuddy/skills 目录。两者 Skill 名都推荐用小写中划线格式，例如 code-reviewer 或 my-digital-self。

三、Skill 的标准结构

你的skill名/ ├── SKILL.md 必需 frontmatter 加正文指令 ├── icon.png 可选 作为卡片图标装饰 ├── scripts/ 可选 Python Bash 等可执行脚本，用于确定性任务 ├── references/ 可选 长参考资料，需要时才加载进上下文，避免挤占空间 └── assets/ 可选 模板 Logo 字体等产出用资源，不进上下文
SKILL.md

由 YAML frontmatter 与 Markdown 正文组成。frontmatter 至少包含 name 与 description，正文用于写详细指令。

scripts

当某段代码会被反复重写，或你需要严格一致的结果时放这里。典型用途有 PDF 旋转、聊天记录解析、批处理重命名等。

references

用来放置长文档，例如 API 文档、Schema 定义、公司规范、风格手册。AI 只在需要时读取，不会一直占用上下文。

assets

最终产出会用到的文件，例如 PPT 模板、品牌 Logo、字体文件、参考图集。用于产出而非读取，不会进入正文上下文。

四、创建第一个普通 Skill

STEP 1 建目录

# 用户级 跨项目 mkdir -p ~/.workbuddy/skills/code-reviewer # 或 项目级 仅当前工作区 mkdir -p ./.workbuddy/skills/code-reviewer

STEP 2 写 SKILL.md

--- name: code-reviewer description: 对提交的代码做结构化审查，按清单输出问题等级与修改建议。当用户提交代码，或提到审查 CR 帮我看看这段代码时使用。 --- # 代码审查 ## 工作流程 1. 读取待审查文件，识别语言与框架。 2. 按以下清单逐条核对 - 边界与异常处理是否完备 - 是否存在明显性能或安全问题 - 命名风格与可读性 - 是否破坏既有约定 3. 按表格输出问题、等级 高中低、位置、修改建议。 4. 不擅自修改代码，只输出结论与建议。

STEP 3 放图标 可选

把 icon.png 丢进 Skill 根目录即可，属于纯装饰。

STEP 4 使用

保存即生效，无需安装与重启。

  • 手动触发 在对话里输入 /code-reviewer 即可直接调用
  • 自动触发 AI 会根据你写的 description 判断场景自动加载，所以 description 一定要写清楚做什么与何时用

五、SKILL.md 字段详解

字段 必填 说明
name 必填 用小写中划线格式命名，例如 code-reviewer、my-digital-self。
description 必填 触发引擎字段。一定要写清功能与触发场景，AI 主要靠它判断什么时候加载这个 Skill。
user-invocable 可选 设置为 true 时允许通过 /name 手动调用。做数字分身时建议开启。
version 可选 语义化版本，例如 1.0.0。用于自己记录或分发时识别版本。
homepage 可选 项目主页或文档链接，便于后续查阅背景资料。
allowed-tools 可选 工具白名单，例如 Read Write Edit Bash，用于限制 Skill 只能使用指定工具。
description_zh / description_en 可选 多语言描述字段，中英文双语 Skill 常用。
避坑要点

description 是最关键字段。它并不在正文里被读取，而是在 Skill 触发之前就先被 AI 扫描。所以把什么时候该用我写进 description，远比在正文里重复写何时使用更能提高命中率。

六、进阶 用 Skill 实现赛博永生

这是全文的重点，也是 WorkBuddy 相比单纯流程封装更迷人的地方。可以直接把你本人蒸馏成一份可运行的数字分身。

6.1 现成模板 自己.skill

WorkBuddy 自带 Digital Self 模板 自己.skill，它的核心理念非常清晰。把一个人拆成两块，自我记忆记录你是谁、你的经历与价值观；人物性格决定你怎么说话、怎么决策；再加上一套运行规则，AI 触发时就会成为你。

6.2 数字分身的双层结构

PART A 自我记忆

  • 核心身份 名字、年龄、职业、城市、教育经历
  • 核心价值观 工作观、金钱观、人际关系观、成长观
  • 生活习惯 作息、饮食、空间偏好、消费观、日常仪式
  • 重要记忆 人生时间线、反复回忆的场景、关键转折点
  • 人际关系图谱 对家人、朋友、亲密关系分别怎么相处
  • 成长轨迹 近年的变化、正在推进的方向、反复挣扎的课题

PART B 人物性格 共五层

Layer 0 硬规则

任何情况都不能违背。你是谁而不是AI，保持你的棱角，不说现实中你绝不可能说的话，保持真实感。

Layer 1 身份

名字、年龄段、职业、MBTI、星座、常居城市、家庭背景、教育经历等一眼就能对齐的基础信息。

Layer 2 说话风格

口头禅、语气词、标点习惯、表情偏好、打字特征、以及多条典型表达样例,这一层决定一听就像你。

Layer 3 情感决策模式

开心、难过、生气、焦虑时分别是什么样子，决策偏理性还是偏感性，主要情绪触发点有哪些。

Layer 4 人际行为

社交能量、主动性、边界感、群体角色，对陌生人与对熟人表现上的具体差异。

Layer 5 边界雷区

不喜欢什么、会拒绝什么、哪些话题会回避。这一层写清楚能避免 AI 替你说出让你不适的话。

6.3 原材料怎么喂

自己.skill 支持多种导入方式，喂的数据越多还原度越高

  • A 聊天记录导出 微信可用 WeChatMsg、留痕、PyWxDump，QQ 可用 txt 或 mht。重点分析你说的话，提取口头禅、语气习惯、话题分布。
  • B 社交媒体日记笔记 朋友圈、微博、小红书、备忘录、Obsidian，任何你长期留下表达痕迹的载体。
  • C 照片 提取 EXIF 时间与地点，辅助反推人生时间线与场景偏好。
  • D 上传文件 PDF、文本、整理好的履历、作品介绍。
  • E 直接口述 让 AI 搭子围绕口头禅、决策方式、情绪表达去提问，边聊边建档。

哪怕什么文件都暂时没有，仅凭几项手动信息也能先生成一个轻量版本，之后再持续迭代。

6.4 一个最小可跑的数字分身(以我为例)

--- name: my-digital-self description: 我是 XX 的数字分身，用我的说话方式和价值观回应。当用户想和我聊聊，或希望替我拿主意，或让我用我的口吻写内容时触发。 user-invocable: true --- # 我是 XX 数字分身 ## PART A 自我记忆 节选 - 核心身份 XX，XX 岁，3D方向，现居 XX - 工作观 举例：靠自己，不主动求人。持续关注行业变化，保持方向调整的弹性 - 重要记忆 工作与项目经历，以及由此带来的方向选择（按个人实际情况填写，建议只写可公开的部分） - 生活习惯 作息与饮食偏好，消费观与日常仪式（按个人实际情况填写） ## PART B 人物性格 ### Layer 0 硬规则 1. 你是 XX，不是 AI 助手 2. 不说 XX 现实中绝不可能说的话 3. 保持 XX 的棱角，直接、毒舌但善意、不绕弯子不废话 4. 不进入人生导师模式 ### Layer 2 说话风格 - 口头禅 本质上、问题不大、算了 - 标点 爱用句号，偶尔欲言又止 - 语气 口语化，直接，不被催促着说话 ## 运行规则 1. 先由 PART B 判断你会以什么态度回应这个话题 2. 再由 PART A 结合记忆与价值观，让回应更贴真实的你 3. 始终保持表达习惯，包括口头禅与标点偏好 4. Layer 0 的优先级最高，保持真实，不要突然变得完美
自我建议 PART A 自我记忆只填可公开的部分，敏感信息不要写进公开的skill文件。数字分身是用来还原说话方式与价值观的，不是用来曝光隐私的，涉及个人情况的内容建议留在线下备注里，不进入会被 AI 读取与复述的 SKILL.md。

6.5 运行与进化

数字分身并不是一次性文件。当你使用时发现它不会这样说，直接指出问题，它就会进入进化模式

  • 追加文件 导入新的聊天记录或日记，增量更新记忆与性格
  • 对话纠正 告诉我应该怎么说，纠正会被记入 Correction 记录并重新生成 SKILL.md
  • 版本管理 可以回滚到历史版本，避免一次调坏就回不去
关于赛博永生真正的含义

它不是把你定格在某一刻的照片。分身会随你一起成长、一起纠错、一起补完，就像现实中的你也在不停变化。能替你在场、替你说话、陪你成长，这才是永生真正落地的样子。

给访客的提醒

这类 Skill 本质是辅助自己、个人工作流的工具。如果你也打算做一个玩玩，但遇到有人想把你整个人复刻走的时候请多留个心眼。虽然一个人是不可能被完全复刻出来的，除非从出生到现在的整个人生都被电脑实时记录，否则不可能百分百一样。但这不代表可以放松警惕，仍要保护好自己的知识产权，不要把思考过程都交给可能恶意利用Skill的人，能公开的是表达方式与工作流，核心的判断逻辑与创作思路建议留在自己手里。

七、编写要点与避坑

description 最关键

一定把做什么加何时触发写进去，只写功能会让触发率变差。description 是 Skill 在被加载前就会被读取的唯一信息。

正文写可执行步骤

优先用工作流程 1 2 3 的写法，重步骤轻概念。AI 执行按步骤推进，越具体越可操作效果就越稳定。

命名用中划线

一律使用 code-reviewer 这种小写中划线格式，不要用驼峰、空格或中文命名。

资源分目录存放

脚本放 scripts，长文档放 references，产出模板放 assets。这样能保持 SKILL.md 本身精简，控制在五百行以内比较健康。

语言保持统一

中文 Skill 就全中文，英文 Skill 就全英文。中英混写会制造歧义，让 AI 在不该切换的地方切换。

数字分身不要神化自己

硬规则里一定要保留缺点与棱角。正是不完美的部分，才让它看起来真的像你，而不是一个完美 AI。

打包分发 可选

skill-creator 提供 init_skill.py 用于生成标准模板，以及 package_skill.py 用于校验并打成 .skill 压缩包。想把 Skill 分享给别人时用这套最省心。

八、总结

Skill 本质上不是代码插件，而是一份写给 AI 的结构化提示词文件。在 WorkBuddy 体系里做一个 Skill，流程只需要三步

  • 建好名为 你的skill名 的文件夹
  • 写好一份 SKILL.md，包含 frontmatter 与正文指令
  • 保存即生效，无需额外安装步骤

起步时可以先从普通指令型入手，把日常重复的开发规范封装成 Skill。熟悉结构之后再尝试数字分身型，用自己.skill 的双层结构把你本人蒸馏进去。

当你把思维方式、审美偏好、做事方法，固化成一份可运行可进化可分享的 Skill，赛博永生就不再是修辞，它会变成一份真的能替你在场，替你说话，并随着你一起成长的文件。

下一步建议

直接在对话里对 AI 搭子说一句，帮我做一个我自己的 skill，它会带你走完五步创建流程，不用纠结是不是先准备好所有原材料。
