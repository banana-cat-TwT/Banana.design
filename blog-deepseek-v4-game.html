DeepSeek V4 正式版生成网页开放世界游戏研究日志

网页游戏生成 vs 正经游戏引擎开发——玩玩看
📅 2026年7月 🏷️ 大模型 · AI游戏 · 研究日志 🔧 DeepSeek V4 · 网页游戏
DeepSeek AI游戏生成 LLM 网页开发

📖 背景

前两天在B站上看到有博主发布了一个非常有意思的视频——用 DeepSeek V4 正式版 直接生成了一套能在网页上跑通的开放世界游戏。虽然老实说，网页游戏生成对于正经的游戏引擎开发来说可能没什么太大用处，但好奇心驱使我还是想亲自玩玩看。

毕竟，AI在游戏开发领域的边界到底在哪里？能不能从"辅助工具"进化到"独立创作者"？这个问题本身就很值得探索。

于是我用完全相同的指令，在我当前的 DeepSeek 版本上也生成了一个 GTA 风格的开放世界网页游戏——「滨湾市 (Binhai City)」，来对比与正式版的差距。

🔍 DeepSeek V4 新旧版本判断方法

在研究过程中，我发现了一个有趣的现象：目前很多用户（包括我自己）用的还不是真正的 DeepSeek V4 正式版。那怎么判断自己用的是新版还是旧版呢？

💡 正式版用户的判断标准

正式版用户发现，区分 DeepSeek V4 新旧版本的一个简单方法是看它生成回复时的开头用语：

  • 🔵 "Let me ..." 开头 → 新版 DeepSeek V4 正式版
  • 🟡 "I am ..." 开头 → 旧版

这个细节虽然很微妙，但在实际使用中确实能帮助判断版本。目前我的版本还是旧版，生成时以 "I am" 开头，暂时还没体验到正式版的新能力。

�️ 实验项目：滨湾市 (Binhai City)

使用与正式版用户相同的 prompt 指令，在我的旧版 DeepSeek 上生成了一个 GTA 风格的网页开放世界游戏。项目采用 单文件架构（index.html，约 128KB），通过 CDN 加载 Three.js 0.185.1，双击即可运行，无需任何服务器。

技术架构

  • 3D 引擎：Three.js 0.185.1（CDN import map 加载）
  • 渲染：WebGLRenderer + PBR 材质 + 日夜循环 + 雾效
  • 物理：自制 arcade 物理引擎（无外部依赖）
  • 碰撞检测：AABB + 地面高度图
  • 纹理/美术：全部 Canvas 2D 程序化生成，零外部资源
  • 音效：全部 WebAudio 程序化合成
  • 文件架构：单文件 index.html，包含全部 HTML/CSS/JS

六阶段开发计划

  1. 骨架搭建：场景初始化、游戏主循环、输入系统
  2. 车辆系统：JSON 声明式零件定义 → 3 种车型（轿车/跑车/SUV），加速/制动/转向/手刹漂移，第三人称跟随相机
  3. 道路与城市：600m×600m 城市地图，道路网络图（节点-边结构），16 种建筑类型（银行、商场、办公楼、酒店、公寓、警察局、医院、加油站、餐厅、仓库、便利店等），路灯、树木、护栏、集装箱、码头水域
  4. 玩家与交互：程序化人物模型，步行/驾驶无缝切换（E 上车/F 下车），相机切换，游戏状态机（LOADING → MAIN_MENU → FREE_ROAM/DRIVING/MISSION_ACTIVE/PAUSED/INDOOR）
  5. 音频与 UI：引擎声合成器（随转速变调）、轮胎摩擦声、碰撞金属声、脚步声、3 个电台 BGM 频道、HUD 速度表、Canvas 2D 小地图（带 GPS 导航）、暂停菜单、教程系统
  6. 任务与打磨：5 个剧情任务（初来乍到→城市巡游→紧急快递→高速追击→码头风云），日夜循环、屏幕震动、建筑室内系统（可进入玩家公寓和酒店大堂）

⚖️ 新旧版本对比：天差地别

同样的指令，DeepSeek V4 正式版和我的旧版生成出来的东西完全不是一个量级。我的旧版生成结果存在以下明显问题：

🔴 旧版（I am...）的主要问题

  • 碰撞体严重缺失：除了房子（建筑）有基本的碰撞检测外，其他所有场景部件——路灯、树木、护栏、集装箱等——全部可以直接穿模，角色能直接走过去
  • 美术资产简陋：建筑和场景物件都是最基础的 BoxGeometry/CylinderGeometry 组合，程序化纹理也相对粗糙，和正式版生成的"比较像个人样"的美术效果差距明显
  • 整体观感粗糙：虽然功能框架搭起来了（能开车、能走路、能上下车、有任务、有音效），但整体感觉就是"勉强能跑"，离"像样"还有很大距离

相比之下，B站博主用 DeepSeek V4 正式版生成的游戏，美术资产明显更精致，碰撞检测也更完善，整体效果更像一个"正经游戏"。这印证了那个判断标准——"Let me" 和 "I am" 开头的版本，能力差距确实是巨大的。

🎮 旧版生成的实际效果

虽然整体简陋，但也不是一无是处。旧版还是成功实现了以下功能：

  • 驾驶体验：轿车、跑车、SUV 三种车型可以正常驾驶，手刹漂移手感尚可，第三人称相机跟随也基本流畅
  • 城市规模：600m×600m 的地图不算小，道路网络、建筑布局、装饰物都按计划生成了
  • 步行/驾驶切换：E 键上车、F 键下车，玩家可以在城市中步行探索再随时上车
  • 建筑室内系统：玩家公寓和酒店大堂可以进入，室内有简单的家具布置（床、桌、椅、书架、吊灯、前台、沙发、盆栽等），虽然都是方盒子拼的
  • 5 个任务：从新手引导到追车、送货，任务系统框架完整
  • 音效系统：引擎声、轮胎摩擦声、碰撞声、电台 BGM 都有，算是可用的程度
  • 小地图：Canvas 2D 绘制，带 GPS 导航路径线
  • 日夜循环：太阳位置、环境光、雾色随时间渐变
⚠️ 总结：旧版生成的游戏"框架有了，但细节全是窟窿"。就像一个只有骨架的房子，能遮风挡雨但远谈不上舒适。正式版用户展示的效果明显更接近"成品"。

🤔 思考：AI游戏开发边界在哪里？

这次对比实验让我对AI在游戏开发中的角色有了更清晰的认知：

  1. 同一模型的不同版本，能力差距巨大：同样的 prompt，"Let me" 版本和 "I am" 版本生成的代码质量天差地别。这不仅仅是代码量的问题，而是对整个游戏系统的理解深度——碰撞检测、美术细节、交互逻辑，正式版明显更"懂"游戏开发
  2. AI目前最适合做"快速原型"：对于验证想法、快速出Demo，AI的效率确实惊人。一个128KB的单文件HTML就能跑出一个可驾驶的3D开放世界，这在以前是不可想象的
  3. 但"生产级游戏"还需人类：真正的游戏开发涉及大量非代码因素——美术风格统一、性能优化、用户体验设计、版本迭代等，AI目前还无法胜任
  4. AI作为"协作伙伴"最有价值：不是替代开发者，而是加速开发流程中的重复性工作，让开发者能专注于创意和设计
