AI 3D 大模型研究日志（底层 · 数据 · 算法）

2026年11月 · 研究整理 · 面向 AI 3D 技术岗位

水密网格 法线约定 PBR 训练数据 多模态3D 数据技术美术

定位：这一篇和前面四篇有什么不同

之前的 Meshy / Tripo / 混元3D / AI生成3D合集，是从应用层记录各家平台的生成效果、功能与局限。这一篇换个角度，往下钻到底层——大模型 3D 方向的岗位（多模态大模型 3D、数据技术美术、大模型算法、AI 3D 技术美术）每天都在跟哪些底层知识打交道：几何、网格、渲染约定、PBR、训练数据质量。

这些底层知识决定了喂给模型的 3D 数据到底是「好数据」还是「坏数据」，也决定了模型生成出来的资产能不能真正进引擎、能不能被渲染管线正确显示。下面按「几何 → 渲染约定 → 材质 → 数据质量 → 岗位」逐层整理。

几何与网格：水密、流形、法线一致性

水密（Watertight）指一个网格是「封闭的 2-流形」——没有边界边、没有破洞，能够明确地包住一个体积。判断标准：每条边恰好被两个面共享，从任意点出发不穿出表面。

  • 为什么重要：体素化（Voxelization）、符号距离场（SDF）、布尔运算、四面体网格、物理碰撞、3D 打印都假设表面是封闭的。很多 3D 生成模型的表示（占用场 Occupancy Field、SDF、tetrahedral）都需要水密输入。
  • 非水密对训练的影响：体积歧义、内外不明确、法线在破洞处乱翻，模型学到的「形状」会在开口处塌掉或出错。

流形（Manifold）：局部上每个点都像一块平面（圆盘邻域）。非流形常见于——一条边被 3 个以上面共享、两个体只靠一个点/一条边相连（蝴蝶顶点/边）。非流形网格在重拓扑、展 UV、SDF 计算时都会崩。

法线一致性：所有面法线应统一朝外。如果一半朝里一半朝外，光照和体积计算都会错。对训练数据来说，法线方向不一致是「脏数据」的直接来源。

数据质检第一关：把模型丢进「看背面 + 看线框 + 看边界边（boundary edge）」三个视图扫一遍，水密/流形/法线问题基本都能暴露。

渲染约定：为什么 OpenGL 和 DirectX 的法线方向不一样

这是最典型的一个「底层约定」问题。法线贴图用 RGB 三个通道存切线空间法线：R = 切线 X，G = 副切线 Y，B = 法线 Z。OpenGL 和 DirectX 的区别就出在 G（Y/上下）通道上。

根因是纹理坐标原点的约定不同：OpenGL 把纹理坐标原点放在左下角，DirectX 放在左上角。这意味着两张图的 V 轴（竖直方向）是上下相反的。法线贴图既然存的是切线空间的 Y 分量，而 V 轴被翻转，那么同一个「朝上」的法线，在两种约定里存的 G 通道数值就正好符号相反。

维度OpenGL 约定DirectX 约定
纹理坐标原点左下角 (0,0)左上角 (0,0)
法线贴图 G 通道（Y）朝上（+Y 向上）朝下（+Y 向下，G 取反）
典型引擎Unity（可导入时翻转）Unreal（默认 DX 风格）
用错的表现凹凸反向（凸变凹、凹变凸），在斜射光下、接缝处尤其明显

对训练数据的影响：如果数据库里两种约定的法线贴图混着用、又不做统一翻转，模型会学到互相矛盾的法线方向分布，生成结果的法线会乱，进引擎后光影错乱。所以数据管线里「法线贴图约定统一」是必做的一步。

PBR 与金属工作流

PBR（Physically Based Rendering）的核心是能量守恒 + 微表面 BRDF，把材质拆成一组物理量：Albedo（基础色）、Metallic（金属度）、Roughness（粗糙度）、Normal（法线）、AO（环境光遮蔽）。

金属工作流（Metallic/Roughness）是当前主流：用一张 Metallic 贴图区分「金属 vs 电介质」，用 Roughness 控制微表面粗糙度。与之相对的是高光工作流（Specular/Glossiness），Unreal 早期常用，现在更推荐金属工作流。

贴图合理取值 / 判断脏数据的典型表现
Albedo 基础色只含颜色，不含光照/阴影把烘焙光照、阴影、高光烤进颜色图
Metallic 金属度基本是二值：0（电介质）/ 1（金属），过渡区只出现在金属边缘到处是 0~1 的灰阶、金属与非金属边界糊成一团
Roughness 粗糙度0（镜面）~ 1（哑光）连续，但同一材质应统一同一表面粗糙度忽高忽低、突然黑一块/白一块
Normal 法线约定统一（见上一节）GL/DX 混用、接缝处方向翻转

对训练数据的影响：如果训练集的 Albedo 里混着光照残留、Metallic 数值乱、Roughness 突变，模型就会学到「光照当材质」「金属度灰阶」「粗糙度噪点」这些错误模式，生成结果再重新打光就会露馅。

训练数据的好坏：什么让数据训出来是好模型

把前面几节串起来，就是一条「数据质量 → 模型质量」的因果链。判断一批 3D 训练数据的好坏，基本看这五点：

  • 几何干净：水密、流形、无自相交、无退化三角形、法线统一朝外、面数分布合理（视觉中心给足面数撑剪影）。
  • 贴图物理正确：PBR 数值合理、Albedo 无光照残留、法线约定统一、无接缝、无烘焙阴影残留。
  • UV 布局合理：无重叠、无拉伸、接缝放在不显眼处。
  • 多视角一致：多视图数据（图像→3D）要求不同视角下同一物体的几何/材质一致，否则模型学到矛盾外观。
  • 标注规范：命名、类别、标签一致，方便检索与配比。

一句话总结：好数据 = 几何上「可计算」（水密/流形/法线一致）+ 材质上「物理正确」（PBR 数值合理、约定统一）+ 视角上「可对齐」。这三条任何一条塌了，模型都会把「脏」当成「规律」学进去。

训练数据清洗：具体案例

把上面三条标准落到具体动作上，沿「几何 → 渲染 → 材质 → 视角 / 标注」的主线，每个案例按「问题 → 识别 → 清洗 → 对训练的影响」展开。

① 几何清洗

案例 1 · 破洞修复（水密化）

  • 问题：扫描或生成的模型有破洞，存在边界边（boundary edge），不是封闭体积。
  • 识别：Max 里用 polyop.getNumOpenEdges 数开放边、高亮边界边，或直接看线框破口。
  • 清洗：补洞（Cap Holes）、删掉内部/多余面，必要时重拓扑成水密体。
  • 影响：SDF / 占用场 / 四面体训练都要求水密；破洞会导致体积歧义，法线在洞口乱翻。

案例 2 · 非流形修复

  • 问题：一条边被 3 个以上面共享，或两个体只靠一个点 / 一条边相连（蝴蝶顶点 / 边）。
  • 识别：流形检测、统计每条边的共享面数。
  • 清洗：删除多余面、焊接重复顶点、拆开仅点 / 边相连的部件。
  • 影响：非流形会让重拓扑、展 UV、SDF 计算直接崩掉。

案例 3 · 法线方向统一

  • 问题：面法线内外混翻，一半朝里一半朝外。
  • 识别：双面光照 + 背面视图，看颜色异常的面。
  • 清洗：统一法线朝外（Unify Normals）、翻转错误面。
  • 影响：法线不一致是「脏数据」最直接的来源，渲染与体积计算都会错。

② 渲染约定清洗

案例 4 · GL / DX 法线贴图统一

  • 问题：库里混入 OpenGL 与 DirectX 两种约定的法线贴图（绿通道方向相反）。
  • 识别：看绿通道（G）朝上还是朝下，或进引擎对比凹凸方向。
  • 清洗：统一翻转到一种约定——Unreal 用 DX、Unity 用 GL，导入时选对，或批量翻转 G 通道。
  • 影响：约定混用会让模型学到互相矛盾的法线分布，生成结果法线乱、光影错乱。

③ 材质（PBR）清洗

案例 5 · Albedo 去光照

  • 问题：基础色图里烘焙了阴影、高光、AO。
  • 识别：Albedo 上能看到明显明暗 / 阴影区域。
  • 清洗：去光照（de-lighting），用光照估计 / 逆渲染把纯 albedo 分离出来。
  • 影响：光照残留会让模型把「打光」当成「材质」，重打光就露馅。

案例 6 · Metallic / Roughness 规范化

  • 问题：metallic 到处是灰阶、roughness 在同一表面突变（忽高忽低、突然黑 / 白一块）。
  • 识别：灰度直方图看异常分布。
  • 清洗：metallic 阈值二值化、roughness 平滑统一。
  • 影响：数值乱会让模型学到错误材质分布（如粗糙度噪点）。

④ 视角 / 标注 / 去重

案例 7 · UV 重叠与拉伸

  • 问题：UV 重叠、拉伸严重、接缝位置不合理。
  • 识别：棋盘格贴图检查拉伸、重叠检测。
  • 清洗：重展 UV、修复重叠、把接缝移到不显眼处。
  • 影响：UV 烂会导致贴图烘焙 / 重投影质量差，接缝处脏。

案例 8 · 多视角一致性

  • 问题：image-to-3D 的多视角图，同一物体在不同视角下材质 / 几何不一致。
  • 识别：跨视角对比同一特征点。
  • 清洗：剔除不一致视角、统一光照环境与相机。
  • 影响：视角不一致会让模型学到矛盾外观，重建产生歧义。

案例 9 · 去重与类别平衡

  • 问题：数据集重复、低质样本、类别不平衡。
  • 识别：哈希去重、质量评分过滤、类别统计。
  • 清洗：去重、过滤低分样本、重采样平衡类别。
  • 影响：类别不平衡会让模型偏向高频类别，生成多样性下降。

九个案例串起来就是一条可落地的清洗流水线：先修几何（水密 / 流形 / 法线）→ 再统一渲染约定（GL/DX 法线）→ 再清材质（去光照 / 数值规范化）→ 最后清 UV / 视角 / 去重。这条流水线跑完，喂给模型的数据才谈得上「干净」。

岗位知识地图

这套底层知识，正好对应大模型 3D 方向几类岗位的日常：

  • 多模态大模型 3D 方向：训练 / 微调 text-to-3D、image-to-3D、多视图重建模型，关心数据配比、表示方式（SDF / 占用场 / 四面体 / 高斯）、损失函数与生成质量。
  • 数据技术美术（Data TA）：数据清洗、标注、规范制定、渲染约定统一、几何质量检查——上面水密/法线/PBR 那套就是 TA 手里最常用的「筛子」。
  • 大模型算法：网络结构、训练策略、数据增强、评测指标，需要理解「什么样的输入会让模型学得好/学坏」。
  • AI 3D 技术美术：把 AI 生成的资产接进引擎管线，修几何、补拓扑、PBR 化、统一法线约定，让「能看」的生成结果变成「能进项目用」的资产。

这四个岗位的共同底座，就是「几何 + 渲染 + 材质 + 数据」这一整套底层知识。这也是这一篇要沉淀的东西。

小结

底层问题决定上层质量：水密/流形/法线决定几何能不能算，OpenGL vs DX 约定决定渲染对不对，PBR 金属工作流决定材质正不正确，这三者合起来决定训练数据是好是坏，最终决定大模型生成出来的 3D 资产能不能真正用起来。

这一篇会持续补充——后面做工具、做数据、做算法时遇到的新问题，都会按这条「几何 → 渲染 → 材质 → 数据 → 算法」的主线继续往里填。
