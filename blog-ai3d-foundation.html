AI 3D 大模型研究日志（底层 · 数据 · 算法）

2026年9月 · 研究整理 · AI 3D 的底层数据与管线

水密网格 法线约定 PBR 训练数据 多模态3D 数据技术美术

定位：这一篇和前面四篇有什么不同

之前的 Meshy / Tripo / 混元3D / AI生成3D合集，是从应用层记录各家平台的生成效果、功能与局限。这一篇换个角度，往下钻到底层：做 AI 3D 这条链路的人每天在跟哪些底层知识打交道，包括几何、网格、渲染约定、PBR、训练数据质量。

这些底层知识决定了喂给模型的 3D 数据到底是好数据还是坏数据，也决定了模型生成出来的资产能不能真正进引擎、能不能被渲染管线正确显示。下面按四层架构（数据 → 算法 → 评测 → 落地）逐层整理。

四层架构总览

AI 3D 生成是一条四层闭环的数据链，不是单向流水线：数据层 → 算法层 → 评测层 → 落地层，而评测和落地的反馈会回流给数据层与算法层。

从零到一：整条链路完整走一遍

在钻进每一层的细节之前，先把从零到一的完整落地过程按时间顺序走一遍。后面所有章节都是在解释这里某一步"为什么难、怎么做"。读的时候可以对号入座：每一步都有明确的输入、动作、交付物、进入下一步的门槛，门槛达不到就不要往下走。

第 0 步：立项与定目标（产品牵头）

先回答三个问题：生成什么（角色 / 场景 / 道具 / 贴图）、给谁用（内部美术提效还是外部用户直接生成）、什么叫"能用"（进引擎可直接用，还是生成后人工修）。这一步要定下上线标准、目标成本、目标周期，例如"道具类资产，生成后人工修不超过 30 分钟，面数 2 万以内，可直接进 Unity"。标准不定，后面每一层都会各说各话。

第 1 步：备数据（数据侧，最上游）

按目标采集 / 采购 / 合成原始模型，然后走清洗流水线：修几何（水密 / 流形 / 法线）→ 统一渲染约定（GL/DX 法线）→ 清材质（去光照 / PBR 数值规范化）→ 清 UV / 视角 / 去重，最后定标注与命名规范、做类别与质量配比。关键动作是先把评测集冻结：从可用数据里按类别和风格抽样形成固定评测集，否则后面每次训完都无法公平比较。

第 2 步：训模型（算法侧）

先定表示（SDF / 占用场 / 网格 / 多视角图像），表示决定能生成什么、需要什么数据、导出干不干净；再定网络与训练配置，跑训练、看曲线、调数据配比、做消融。每出一版就用冻结评测集跑分，并翻 bad case 归因：是数据问题就回流第 1 步，是结构问题才改模型。

第 3 步：建评测（评测侧，连接上下游）

评测有两道：训练前的数据质量评测（决定哪些数据能进训练集，回流数据层）和训练后的生成质量评测（决定能不能上线）。生成质量不能只看几何 / 纹理指标，还要加下游可用性评测：导出干净度、拓扑可绑定性、减面后质量保持、进引擎渲染是否正确。指标要和美术感受对齐，否则会出现"分数达标、美术说不能用"。

第 4 步：接落地（落地侧，最靠近项目）

把通过评测的生成资产接进真实管线：修拓扑与 UV、PBR 材质规范化、LOD 与减面、绑定与动画适配、性能与兼容测试，能自动化的环节写成管线脚本。这一层要量化返修率与单件人工耗时，这是产品判断"值不值"的核心数字。

第 5 步：上线与灰度

不要一次全量。先小范围灰度：内部美术试用或外部小流量开放，配 A/B 对比和人工抽检，盯住通过率、返修率、用户留存与投诉。上线标准在第 0 步已经定好，达标才扩大范围。

第 6 步：回收反馈并回流，进入下一轮

把上线后的反馈翻译成技术动作并归因到具体层："生成的不像"可能是数据分布不对（回第 1 步）、表示能力不够（回第 2 步）、评测标准没覆盖（回第 3 步）、或落地修得不对（回第 4 步）。归因清楚再排优先级，链路因此形成闭环，而不是每次笼统地"再优化一下"。

步骤上游输入交付物进入下一步的门槛

产品团队在这条链路上每天在问什么

1. 瓶颈现在在哪一层？生成质量达标但返修率高，瓶颈在落地层，应先投管线自动化；bad case 主要是破洞和法线错乱，瓶颈在数据层，应先投清洗。资源有限只打瓶颈，不要四层平均用力。

2. 每一层的成本和周期是多少？清洗一万个模型几天、训一版几张卡几天、TA 修一个几小时，没有这些数，排期和定价都是空的。

3. 上下游接口约定清楚了吗？数据交给算法的格式、算法交给评测的输出、评测结论如何回流，接口不清就会反复返工。

4. 用户反馈落回哪一层？每条反馈都要能翻译成具体层的具体动作，否则迭代就是碰运气。

一句话：这条链路是"标准先行、数据打底、评测把关、落地验收、反馈回流"的闭环。产品团队是翻译官和调度员——把上游能力翻译成下游价值，把下游反馈翻译成上游动作；技术团队则保证每一层的交付物达到进入下一步的门槛。

几何与网格：水密、流形、法线一致性

水密（Watertight）指一个网格是封闭的 2-流形，没有边界边、没有破洞，能够明确地包住一个体积。判断标准：每条边恰好被两个面共享，从任意点出发不穿出表面。

  • 为什么重要：体素化（Voxelization）、符号距离场（SDF）、布尔运算、四面体网格、物理碰撞、3D 打印都假设表面是封闭的。很多 3D 生成模型的表示（占用场 Occupancy Field、SDF、tetrahedral）都需要水密输入。
  • 非水密对训练的影响：体积歧义、内外不明确、法线在破洞处乱翻，模型学到的形状会在开口处塌掉或出错。

流形（Manifold）：局部上每个点都像一块平面（圆盘邻域）。非流形常见于：一条边被 3 个以上面共享、两个体只靠一个点或一条边相连（蝴蝶顶点/边）。非流形网格在重拓扑、展 UV、SDF 计算时都会崩。

法线一致性：所有面法线应统一朝外。如果一半朝里一半朝外，光照和体积计算都会错。对训练数据来说，法线方向不一致是脏数据的直接来源。

数据质检第一关：把模型丢进看背面 + 看线框 + 看边界边（boundary edge）三个视图扫一遍，水密/流形/法线问题基本都能暴露。

渲染约定：为什么 OpenGL 和 DirectX 的法线方向不一样

这是最典型的一个底层约定问题。法线贴图用 RGB 三个通道存切线空间法线：R = 切线 X，G = 副切线 Y，B = 法线 Z。OpenGL 和 DirectX 的区别就出在 G（Y/上下）通道上。

根因是纹理坐标原点的约定不同：OpenGL 把纹理坐标原点放在左下角，DirectX 放在左上角。这意味着两张图的 V 轴（竖直方向）是上下相反的。法线贴图既然存的是切线空间的 Y 分量，而 V 轴被翻转，那么同一个朝上的法线，在两种约定里存的 G 通道数值就正好符号相反。

维度OpenGL 约定DirectX 约定
纹理坐标原点左下角 (0,0)左上角 (0,0)
法线贴图 G 通道（Y）朝上（+Y 向上）朝下（+Y 向下，G 取反）
典型引擎Unity（可导入时翻转）Unreal（默认 DX 风格）
用错的表现凹凸反向（凸变凹、凹变凸），在斜射光下、接缝处尤其明显

对训练数据的影响：如果数据库里两种约定的法线贴图混着用、又不做统一翻转，模型会学到互相矛盾的法线方向分布，生成结果的法线会乱，进引擎后光影错乱。所以数据管线里法线贴图约定统一是必做的一步。

PBR 与金属工作流

PBR（Physically Based Rendering）的核心是能量守恒 + 微表面 BRDF，把材质拆成一组物理量：Albedo（基础色）、Metallic（金属度）、Roughness（粗糙度）、Normal（法线）、AO（环境光遮蔽）。

金属工作流（Metallic/Roughness）是当前主流：用一张 Metallic 贴图区分金属 vs 电介质，用 Roughness 控制微表面粗糙度。与之相对的是高光工作流（Specular/Glossiness），Unreal 早期常用，现在更推荐金属工作流。

贴图合理取值 / 判断脏数据的典型表现
Albedo 基础色只含颜色，不含光照/阴影把烘焙光照、阴影、高光烤进颜色图
Metallic 金属度基本是二值：0（电介质）/ 1（金属），过渡区只出现在金属边缘到处是 0~1 的灰阶、金属与非金属边界糊成一团
Roughness 粗糙度0（镜面）~ 1（哑光）连续，但同一材质应统一同一表面粗糙度忽高忽低、突然黑一块/白一块
Normal 法线约定统一（见上一节）GL/DX 混用、接缝处方向翻转

对训练数据的影响：如果训练集的 Albedo 里混着光照残留、Metallic 数值乱、Roughness 突变，模型就会学到光照当材质金属度灰阶粗糙度噪点这些错误模式，生成结果再重新打光就会露馅。

训练数据的好坏：什么让数据训出来是好模型

把前面几节串起来，就是一条数据质量 → 模型质量的因果链。判断一批 3D 训练数据的好坏，基本看这五点：

  • 几何干净：水密、流形、无自相交、无退化三角形、法线统一朝外、面数分布合理（视觉中心给足面数撑剪影）。
  • 贴图物理正确：PBR 数值合理、Albedo 无光照残留、法线约定统一、无接缝、无烘焙阴影残留。
  • UV 布局合理：无重叠、无拉伸、接缝放在不显眼处。
  • 多视角一致：多视图数据（图像→3D）要求不同视角下同一物体的几何/材质一致，否则模型学到矛盾外观。
  • 标注规范：命名、类别、标签一致，方便检索与配比。

一句话总结：好数据 = 几何上可计算（水密/流形/法线一致）+ 材质上物理正确（PBR 数值合理、约定统一）+ 视角上可对齐。这三条任何一条塌了，模型都会把脏当成规律学进去。

训练数据清洗：具体案例

把上面三条标准落到具体动作上，沿几何 → 渲染 → 材质 → 视角 / 标注的主线，每个案例按问题 → 识别 → 清洗 → 对训练的影响展开。

① 几何清洗

案例 1 · 破洞修复（水密化）

  • 问题：扫描或生成的模型有破洞，存在边界边（boundary edge），不是封闭体积。
  • 识别：Max 里用 polyop.getNumOpenEdges 数开放边、高亮边界边，或直接看线框破口。
  • 清洗：补洞（Cap Holes）、删掉内部/多余面，必要时重拓扑成水密体。
  • 影响：SDF / 占用场 / 四面体训练都要求水密；破洞会导致体积歧义，法线在洞口乱翻。

案例 2 · 非流形修复

  • 问题：一条边被 3 个以上面共享，或两个体只靠一个点 / 一条边相连（蝴蝶顶点 / 边）。
  • 识别：流形检测、统计每条边的共享面数。
  • 清洗：删除多余面、焊接重复顶点、拆开仅点 / 边相连的部件。
  • 影响：非流形会让重拓扑、展 UV、SDF 计算直接崩掉。

案例 3 · 法线方向统一

  • 问题：面法线内外混翻，一半朝里一半朝外。
  • 识别：双面光照 + 背面视图，看颜色异常的面。
  • 清洗：统一法线朝外（Unify Normals）、翻转错误面。
  • 影响：法线不一致是脏数据最直接的来源，渲染与体积计算都会错。

② 渲染约定清洗

案例 4 · GL / DX 法线贴图统一

  • 问题：库里混入 OpenGL 与 DirectX 两种约定的法线贴图（绿通道方向相反）。
  • 识别：看绿通道（G）朝上还是朝下，或进引擎对比凹凸方向。
  • 清洗：统一翻转到一种约定 Unreal 用 DX、Unity 用 GL，导入时选对，或批量翻转 G 通道。
  • 影响：约定混用会让模型学到互相矛盾的法线分布，生成结果法线乱、光影错乱。

③ 材质（PBR）清洗

案例 5 · Albedo 去光照

  • 问题：基础色图里烘焙了阴影、高光、AO。
  • 识别：Albedo 上能看到明显明暗 / 阴影区域。
  • 清洗：去光照（de-lighting），用光照估计 / 逆渲染把纯 albedo 分离出来。
  • 影响：光照残留会让模型把打光当成材质，重打光就露馅。

案例 6 · Metallic / Roughness 规范化

  • 问题：metallic 到处是灰阶、roughness 在同一表面突变（忽高忽低、突然黑 / 白一块）。
  • 识别：灰度直方图看异常分布。
  • 清洗：metallic 阈值二值化、roughness 平滑统一。
  • 影响：数值乱会让模型学到错误材质分布（如粗糙度噪点）。

④ 视角 / 标注 / 去重

案例 7 · UV 重叠与拉伸

  • 问题：UV 重叠、拉伸严重、接缝位置不合理。
  • 识别：棋盘格贴图检查拉伸、重叠检测。
  • 清洗：重展 UV、修复重叠、把接缝移到不显眼处。
  • 影响：UV 烂会导致贴图烘焙 / 重投影质量差，接缝处脏。

案例 8 · 多视角一致性

  • 问题：image-to-3D 的多视角图，同一物体在不同视角下材质 / 几何不一致。
  • 识别：跨视角对比同一特征点。
  • 清洗：剔除不一致视角、统一光照环境与相机。
  • 影响：视角不一致会让模型学到矛盾外观，重建产生歧义。

案例 9 · 去重与类别平衡

  • 问题：数据集重复、低质样本、类别不平衡。
  • 识别：哈希去重、质量评分过滤、类别统计。
  • 清洗：去重、过滤低分样本、重采样平衡类别。
  • 影响：类别不平衡会让模型偏向高频类别，生成多样性下降。

九个案例串起来就是一条可落地的清洗流水线：先修几何（水密 / 流形 / 法线）→ 再统一渲染约定（GL/DX 法线）→ 再清材质（去光照 / 数值规范化）→ 最后清 UV / 视角 / 去重。这条流水线跑完，喂给模型的数据才谈得上干净。

算法层：表示、网络与训练

算法层的第一性问题不是网络，而是表示方式（Representation） 同一个3D 生成任务，用什么数据结构来表征形状，直接决定了能生成什么、需要什么数据、以及生成结果能不能干净导出。

表示方式

表示特点对数据的要求
SDF（符号距离场）隐式、连续、水密友好，适合可变形 / 光滑表面；难出复杂拓扑要求水密、法线一致
占用场（Occupancy）0/1 内外，实现简单，但边界不够精确水密、内外明确
四面体网格（Tetrahedral）显式 + 体积，可直接进物理 / 有限元，内存大水密、流形
3D 高斯（3DGS）渲染快、可微，适合新视角合成，但表面不严格一致多视角、多视图对齐
NeRF（神经辐射场）连续体积、光照可学，训练慢、难导出干净 mesh一致多视角、相机位姿

注意表示方式与数据层的强耦合：SDF / 占用场 / 四面体都要求水密输入，这正是前面破洞修复那一系列几何清洗存在的根本原因。

网络结构与训练

  • 扩散模型（Diffusion）：当前 text-to-3D / image-to-3D 主流，逐步去噪生成；
  • Transformer / DiT：多模态对齐、序列建模，常用作条件编码器或骨干；
  • 多视图重建（如 MV-Dream 类）：2D 扩散 + 多视图一致性约束，提升几何一致；
  • 大重建模型（如 LRM 类）：单张 / 少量图直接前馈出 3D，推理快、适合规模化；
  • 训练要素：损失函数（几何损失 / 渲染损失 / 感知损失 / 多视角一致性损失）、噪声与学习率调度、大模型蒸馏、数据配比（类别平衡、质量分层）。

评测层：两道评测与指标

评测层其实有两道：训练前的数据质量评测（决定哪些数据能进训练集），和训练后的生成质量评测（决定模型好不好用）。

生成质量评测

  • 几何质量：水密率、流形率、面数合理性、拓扑干净度，回到数据层那套标准；
  • 纹理质量：PBR 数值合理、无接缝、无光照残留；
  • 与参考相似度：FID（2D 渲染图分布）、CLIP Score（文本-图像对齐）、几何相似度（Chamfer Distance、F-Score）；
  • 主观 / 用户评分：人工评测生成结果的观感与可用性。

下游可用性评测（落地层视角）

  • 能否进引擎：FBX / glTF 导出是否干净、PBR 贴图是否齐全；
  • 能否绑定动画：拓扑是否支持骨骼绑定、蒙皮；
  • 能否重拓扑 / 减面：重拓扑、减面后是否仍保持质量。

数据质量评测（训练前，回流到数据层）

  • 数据质检打分：水密 / 流形 / 法线 / 贴图数值的通过率；
  • 回流作用：这些指标直接决定哪些数据可以进训练集，是评测层回流数据层的第一道闸门。

管线实战：从生成产物到可用资产的 5 个难题

这 5 题是 3D 技术美术（AI 方向）在真实产线里最常被问到的：AI 生成出来的东西，怎么变成美术真能用的资产。它们串起来正好是一条完整的分诊线——先清理几何（Q1）、再压住生成阶段的幻觉（Q2）、然后统一尺度与落地（Q3）、接着解决风格同质化（Q4）、最后交给程序化系统拼装（Q5）。每一题的答案都不是「换个更好的模型」，而是在模型外面补一套能自动跑的工程约束。

Q1｜Image-to-3D 的面数超标、黏连、内部空腔，怎么设计全自动清理过滤器

先说清楚为什么要「过滤器」而不是「修复工具」：开放世界的植被和场景道具有几千上万件，人工修一件十分钟就崩了。所以这套东西的设计目标不是修得最好，而是在无人值守的情况下把 85% 以上的资产修到能进引擎，剩下 15% 精准打回人工队列。

整条流水线按顺序分七道闸：

  • 分诊打分。进来先算一组硬指标——面数、水密率、流形边数量、连通分量数、自交数量、包围盒长宽比。按指标直接分成「可直接用 / 可自动修 / 人工」。这一步决定了后面所有环节的工作量。
  • 连通分量清理。分离所有连通块，丢掉面数低于阈值的碎块，这就是去 floaters。注意植被不能一刀切——树叶本来就是一堆独立面片，要按材质槽或语义先判类，再决定「合并」还是「保留」。
  • 内部空腔剔除。这是最容易漏的一步。做法是从物体外部多个方向做射线可见性采样，统计每个面被看到次数，完全不可见的内壳整块删掉。生成的石头、树干内部经常藏着一层完整的内壁，白白吃掉一半面数。
  • 黏连分割。相邻物体被生成成一坨是常见问题。用凹度分析加区域生长（region growing）做面片分割，以法线突变和平面拟合误差作为切割判据，把「椅子腿和椅子面长在一起」拆开。拆不开的再走 SDF/VDB 的连通分析。
  • 水密化与去畸变。补洞用边界环加最小面积三角化；非流形边逐条修；自交用 voxel remesh 后 shrinkwrap 回原表面，比直接做布尔稳健得多。去畸变专门抓三类：法线翻转、退化三角形（面积趋零）、尖刺（局部曲率异常）。
  • 重展 UV 并回烘。这一步很多人会跳过，但必须做。生成模型自带的 UV 基本不可用，清理完几何后要用 xatlas 或 UVAtlas 重新展开，再把原贴图烘焙到新 UV 上，否则纹理全错位。
  • 面数归一 + LOD + 碰撞。按资产类别设目标面数，用 QEM 简化并保护 UV seam 和硬边；顺带生成三级 LOD 与简化碰撞体，一步到位。

工程上两个决定成败的点：一是每个环节都要输出指标并能回退，任何一步质量下降超过阈值就直接打回人工，不要让错误往下游传；二是植被走另一条支线——Alpha card 植被不该当实体几何清理，应该走 cutout 加 billboard，简化时还要保护边界顶点，否则枝条一减就断。整套用 Python 配 trimesh / libigl / Open3D 就能 headless 批跑。

Q2｜不重训基座，怎么在生成前置阶段压住 Janus 问题

Janus 的成因要先讲对：不是模型「不会画脸」，而是每个视角各自独立收敛。2D 先验在任意视角下都会本能地补一张脸，多视角之间又没有任何通信机制，于是正面一张、背面再来一张。既然根因是「视角之间没通信」，解法就都围绕建立跨视角约束展开，不需要动基座权重。

第一招，改采样方式。不要在球面上随机撒独立视角，改成沿同一纬度的环绕轨迹采样，并且让同一 batch 内的多视角共享噪声和潜变量，通过 multi-view attention 或 epipolar attention 互相看得见。MVDream、SyncDreamer 这一代的核心改进就在这。

第二招，加法线约束。用 2D 法线估计模型（StableNormal、Marigold normals 那类）从参考图和多视角图里提取法线，作为几何监督项，约束「渲染法线」和「估计法线」一致。这一招对多脸特别有效，因为背面那张脸的朝向和真实背面法线天然冲突，约束一加就被压下去了。

第三招，加深度一致性。用单目深度（Depth Anything 一类）估计参考图深度，在多个渲染视角上做尺度对齐后的相对深度约束。深度比法线更直接地约束「背面在哪」，能有效防止背部长出多余结构。也可以把深度当 ControlNet 条件塞进多视角生成。

第四招，加对称性先验。先用 PCA 加反射一致性检测出对称平面，然后对几何加镜像对称正则——左右点云做 Chamfer 或直接惩罚偏离量。对称性是个极强的先验，大多数角色和道具都该对称，一旦约束上去，背面的自由度会被大幅压缩。

第五招，后处理检出兜底。生成完，绕物体转一圈渲染 8 到 12 个视角，跑 2D 人脸检测器数脸数。超过 1 张就判定失败，触发重采样或局部重生成。这一步是必须的，因为前面的约束都是软约束，永远会有漏网的。

这套方案不重训基座的代价是推理变慢：多视角渲染次数从个位数涨到几十次，约束项也让优化更难收敛。所以生产上通常分级——先跑便宜的多视角一致性，检测到 Janus 再启用完整的法线加深度加对称约束。关键是「Janus 检测器」这个指标要先建起来，没有它就无法知道约束到底有没有用。

Q3｜尺度归一化与地面贴合，怎么在 DCC 后处理里全自动做

AI 生成的模型有个根本特性：它没有真实尺寸这个概念。尺度是相对的，pivot 通常在原点，朝向是随机的。而游戏资产对这三样都有硬约定，所以必须有一套自动化后处理把它们拉回规范。

第一步，单位与坐标系归一。先判断资产是按米、厘米还是英寸建的，再判断 up 轴是 Y-up 还是 Z-up，用一套转换矩阵统一到项目规范。这一步不做，后面所有数值都白算。

第二步，类别先验定尺度。既然模型自己不知道大小，就从类别反推。做法是对渲染图跑 CLIP 分类，或者直接读生成时的 prompt 里的类别词，然后查一张「类别—典型尺寸」表：椅子座高 0.45m、门高 2.1m、行道树 6 到 8m、垃圾桶 1m。把包围盒的主维度等比缩放到该尺寸。

这里必须强调等比缩放。绝对不能按每个轴独立拉，那会把椅子压扁、把树拉成竹竿，还会让法线全部失真（非等比缩放后法线必须重新归一化才有效）。

第三步，Pivot 修正。生成模型的 pivot 基本都在几何原点，但游戏资产的约定完全不一样，要按类别分：

  • 站立物（椅子、桌子、垃圾桶）：pivot 移到包围盒底面中心，脚底接地；
  • 悬挂物（吊灯、路牌）：pivot 放到顶部挂点；
  • 可拾取物（道具、捡起物）：pivot 放在体积重心，手感和旋转才自然。

重心要用体积积分算，不能只用顶点平均——顶点分布是不均匀的，顶点平均中心常常明显偏离真实重心。

第四步，Snap-to-Ground 的感觉要准。不能直接取最低点，因为一个尖刺就能让整件资产悬空。正确做法是取包围盒底部 5% 高度的顶点，用 RANSAC 拟合平面：

  • 如果拟合出的平面法线与 up 轴夹角小于 15°，说明有平底，直接把该平面贴到 y=0，同时把资产旋正；
  • 如果底部是曲面（石头、树根），退化成用最低点的 1% 分位作为落地点，抗孤立尖刺；
  • 两种情况都要把倾斜角修正掉，否则资产是歪的。

第五步，朝向统一。用 PCA 主轴确定主方向，再用对称性判断正反——对称物体以对称面为基准对齐，非对称物体用「特征面朝向」判定，统一成项目约定的朝向（比如面向 -Y）。

三个必踩的坑：一是缩放后一定要 apply transform，引擎里 scale 不是 1 会引发一堆物理和烘焙问题；二是 pivot 改了要同步到碰撞体和挂点，否则子弹打上去是空的；三是落地后再检查一遍包围盒与贴花/阴影的对齐，倾斜修正有时会带来微小偏移。输出报告要带上 bbox 尺寸、pivot 位置、残余倾斜角三个数，超阈值打回。

Q4｜通用模型风格同质化，怎么建专有风格化生成子管线

开源 3D 大模型的输出高度同质化，是因为它们训练数据基本是写实扫描件。想让模型生成二次元赛璐珞或者特定暗黑写实，光靠 prompt 是不够的——风格不是一句话能描述的，是一整套渲染约定。所以正确做法是建一条「风格化子管线」，而不是调一个参数。

第一环，把风格写成规范。先固化风格定义：色板（有限色阶）、描边宽度与颜色、光影阶梯数（赛璐珞通常 2 到 3 阶）、边缘光规则、材质简化程度（哪些细节必须删）。这份规范是后面所有环节的验收基准，没有它，训出来的模型只能说「感觉不对」。

第二环，合成数据渲染反哺，这是整条管线最关键的一环。用项目已有的高模资产，在统一的 NPR shader 下绕圈渲染多视角，得到大量「风格化图像 + 真实几何」的配对数据。核心要求是渲染参数必须完全固定——光照方向、色阶阈值、描边宽度全部写死，这样 2D 先验学到的是风格本身，而不是某一次打光。

第三环，双 LoRA 微调。不要在 3D 基座上直接硬训，成本高且容易崩。推荐两层：先在 SDXL 这类 2D 先验上训一个风格 LoRA，再训一个类别/结构 LoRA。两个分开的好处是风格可以迁移到新类别，不会一换类别就得重训。

第四环，控制网格嵌入。对二次元角色来说，剪影比细节重要得多——轮廓错了，贴图再精细也不像。所以要用控制网格或参考轮廓做几何条件：把控制网格渲染成深度图和法线图，作为 ControlNet 条件注入生成，强制轮廓一致；或者直接以模板网格做几何锚定，只让模型负责表面细节。这一步是把艺术家的意图硬性灌进去，而不是指望模型猜。

第五环，PBR 转 NPR。生成出来的还是 PBR 贴图，必须做转换：albedo 用 posterize 压缩到有限色阶再映射到色板，去掉高光和法线细节，描边单独走一个 pass（inverted hull 或后处理边缘检测）。这一步不做，风格就只停留在「模型长得像」，渲染出来还是写实的。

两个常见翻车点：一是风格 LoRA 过拟合到训练资产的具体造型，生成的永远像你拿来训的那几件东西。解法是训练集里混入大量不同造型、只共享风格。二是描边宽度依赖分辨率，靠近看粗、拉远看细，必须做成屏幕空间恒定宽度。验收看三个指标：CLIP 风格相似度、与控制网格的剪影 IoU、美术盲测通过率。

Q5｜生成式 AI 怎么和 Houdini PCG 融合，批量出废墟与风化岩石

这题的关键认知是：AI 和 PCG 不该抢同一件事。AI 的强项是「造出没见过的东西」，弱项是「精确、可复现、可参数控制」；Houdini PCG 恰好相反。所以正确的分工是——AI 负责部件级的多样性，PCG 负责装配级的规则与精度。

第一层，AI 出部件库。不要直接生成「一整栋废墟」，而是生成可复用的模块：砖块、断墙、断裂梁、瓦砾、石块。每类出 20 到 50 个变体，一起进库。这里有三条硬约束，缺一条后面就拼不上：

  • 严格统一尺度——砖就是砖的尺寸，不能每个变体大小不一；
  • 严格统一 pivot——一律归到底面中心，方便 copy to points；
  • 严格统一材质与命名——按 @material 属性规范，方便 PCG 驱动。

出库前先跑 Q1 那套清理管线，把 LOD 和碰撞一起生成好。

第二层，Houdini 封装装配规则。用 HDA 把「怎么拼」写成规则。比如断墙：墙基按一定间距布砖 → 中间层按 @damage 参数从库里按权重抽破损变体 → 顶部做不规则切割 → 地面撒瓦砾（数量和分布由 @damage 驱动）。整个过程用 Attribute Wrangle 控制，一个滑杆就把「轻微破损」推到「彻底坍塌」。

第三层，拼接精度的解法是「连接件设计」。这是最容易失手的地方。AI 生成的部件边缘是随机的，两个随机边缘拼一起必然有缝。解法是让部件在生成阶段就带上标准接口：墙面部件边缘切割线对齐到网格，石块底面强制做平，梁的端面做成标准断面。Houdini 侧用 copy to points 加 orient 属性按这些接面对齐，精度就控制住了。

第四层，接缝处理。对齐之后用 boolean 或 VDB 融合消除硬缝；但更自然的做法是故意留不完美——错位几厘米、塞几块碎石、加几条裂缝。真实废墟本来就没有整齐的接缝，过度融合反而假。

第五层，物理合理性检查。简单做法是检查每个碎块的支撑关系（下方是否有接触面），悬空的自动移除或下落；做得细一点可以跑一次 RBD 崩塌解算，再烘回静态。这一步不加，场景里会出现大量浮在半空的砖。

还有一个容易忽略的收益：AI 部件库要带版本 hash，PCG 场景记录下来用的是哪一版部件。否则半年后重新生成场景，废墟长得完全不一样，无法复现。另外材质务必走统一 trim sheet 或 atlas，不然几百种废墟拼出来 draw call 直接爆炸。验收看四个数：缝隙可见率、部件复用率、单场景生成耗时、内存与 draw call。

Q26｜3DGS 场景怎么生成轻量又精准的隐式碰撞体

矛盾的根源很直接：渲染表示和物理表示不是一回事。3DGS 是一堆各向异性高斯椭球，NeRF 是辐射场，两者都没有「表面」这个概念，也没有顶点、边、面，物理引擎的 raycast 和刚体碰撞根本无从下手。所以「生成碰撞体」的本质是先想办法把连续的场重新变回一张面。

第一条路线：表面重建。从 3DGS 里取多视角深度图和不透明度场，做 TSDF 融合，再 marching cubes 出网格。也可以直接用 SuGaR、2DGS 这类方法，让训练时就把高斯压到表面上，导出网格干净得多。出来的网格一定带噪声，必须做平滑、去浮空块、简化、水密化。

第二条路线：凸分解，这是「轻量 + 精准」的平衡点。整场景做一个凸包会严重失真，因为凸包会把凹形全部填平。正确做法是 V-HACD 或 CoACD 做近似凸分解，一个椅子拆成十几个凸多面体。物理引擎对凸多面体是原生支持的，效率高、稳定，还能做连续碰撞检测。这是工程上最推荐的默认方案。

第三条路线：SDF。从点云重建 VDB SDF 或训神经 SDF，适合软体、连续碰撞、体积查询。但每像素或每步求解 SDF 开销大，实时通常要烘成 SDF volume texture，或者干脆再转回网格。

落地时的几个关键判断：

  • 必须分级，不能一视同仁。小物件和远处物体用 AABB 或单个凸包就够，主要交互物才做凸分解，地面用 heightfield 或 trimesh。轻量来自「大部分东西都不精确」。
  • 一定要留一层细网格兜底。凸包在凹角处会浮空，raycast 打上去会和视觉错位。常见做法是凸包管物理，细网格只挂一层 low-cost 的 raycast 层。
  • 动态物体和静态物体分开处理。可移动道具用凸包方便跟随变换，静态场景用 trimesh + BVH 加速结构。
  • 要防重建噪声变成碰撞体。3DGS 常见的浮空高斯（floaters）、半透明的树叶玻璃、地面高光反射，都会被重建成实体几何。必须按不透明度和语义先过滤，透明物体不该生成实体碰撞。

完整流程：3DGS → 多视角深度 + 不透明度 → TSDF / 泊松重建 → 去噪简化 → V-HACD 凸分解 → 烘碰撞 LOD 链 → 运行时按距离和重要性切换。验收用两个数：一是穿插深度（角色能陷进几何多少），二是重建深度与渲染深度的 IoU，这两个数达标才算「精准」。

Q27｜超大尺度 3DGS 场景的分块与流式调度怎么设计

这题的正确类比是 Virtual Texture，不是普通的资源加载。VT 的精髓是三件事：按页切分、用索引表解耦逻辑地址和物理页、按 mip 级别决定加载精度。把这三件事搬到 3DGS 上，就是一套完整的调度系统。

第一，分块。用四叉树或八叉树按空间切块，每块自己存一份高斯数据，并带元信息：AABB、中心、包围半径、高斯数量、字节大小。这里有个 3DGS 特有的坑——高斯椭球会跨块，跨边界的高斯要么复制到多个块（类似 VT 的 border padding），要么按中心归属但把 AABB 外扩。

第二，分层 LOD，这就是 3DGS 的 mip。每块预先烘好几级：完整高斯 → 重要性剪枝 / 高斯合并（lightGaussian、Mini-Splatting 那类做法）→ 降 SH 阶（3 阶降到 0 阶）→ 更远处换成 impostor 布告板甚至代理网格。级数不必多，3 到 4 级就够用。

第三，索引与页池。维护一张全局虚拟地址表，记录每块每级的数据在哪；GPU 上开固定大小的 page pool，运行时只把需要的页搬进来，LRU 淘汰。这一层完全是 VT 的 page table + cache 结构，可以直接照搬。

第四，剔除。四级串起来做：块级视锥剔除（用 AABB）→ 按屏幕空间误差选 LOD → 遮挡剔除（用上一帧深度建 HZB，或用粗代理布告板先渲一遍深度）→ 高斯级不透明度剔除。3DGS 多出来的这一级很重要，因为前面高不透明度的 Gaussians 会挡住后面的，不做就白算。

第五，异步流。IO 线程读盘解压 → staging buffer 分帧上传 → 双缓冲。关键是每帧给一个固定上传预算（比如 8MB），按屏幕贡献排序做优先级队列，再加相机速度预测做预取。不设预算就会出现「转个头卡半秒」。

可以直接借 Cesium 3D Tiles 的层级结构和 LOD 规则，几何 streaming 这块它已经是很成熟的事实标准，把 tile 的 content 换成 3DGS chunk 就行。要盯的指标是：显存峰值、每帧上传带宽、块切换时的卡顿次数。

Q28｜移动端 3DGS 的剔除与 Shader 降级策略

根因要讲清楚：3DGS 每个高斯是一个半透明椭球贴片，按深度排序后做 alpha 混合。这意味着大量像素会被反复混合，Overdraw 直接乘以带宽。而移动端 Adreno 和 Apple Silicon 都是 TBDR 架构，带宽是硬瓶颈，全屏多层混合立刻爆掉。所以移动端不是「怎么优化」，而是「怎么把混合次数砍到能接受」。

数量层：先把高斯总数砍下来。按不透明度、体积、尺度、对最终画面的贡献做重要性剪枝，通常能砍掉 60% 到 80% 而几乎看不出差别。再把参数从 fp32 降到 fp16，SH 系数用 int8 量化，或者直接降到 0 阶只保留基础色。

剔除层：粗粒度块视锥剔除；累积 alpha 提前终止（前面的不透明度累加到接近 1 就不再算后面）；屏幕空间剔除，投影后小于 1 像素的高斯直接丢掉；HZB 遮挡剔除。

排序层：移动端千万别每帧做全量 radix sort，那是 CPU/GPU 双杀。改用分块局部排序，块内预排序一次、每帧只排块序；或者用 tile-based binning，把高斯按屏幕 tile 分桶，每 tile 内单独排序，这就是 tile-based splatting 的思路。

渲染层，真正的降级点：

  • 把 3D 椭球的逐像素求交换成 2D 屏幕空间椭圆，省掉每像素的协方差投影开销；
  • 用 quad 或 billboard 承载，片元里对高斯做低阶近似，别用完整 exp；
  • 限制每像素最大混合层数，比如只叠前 8 到 16 层，超了直接丢；
  • 关掉 MSAA（3DGS 不需要），全链路 half precision，避免片元里的分支；
  • TBDR 上尽量用 framebuffer fetch 读片上内存，避免中途 resolve 造成一次完整带宽往返。

移动端 3DGS 的现实路线可以总结成一句话：大幅剪枝 + SH 降阶 + 2D 屏幕空间 + tile 排序 + 限制层数。代价是牺牲一部分视角相关效果，但换来了带宽可控。另外建议挂一个动态质量开关，按 GPU 帧时间预算实时调整 LOD 和最大层数。

Q29｜3DGS 怎么绑骨骼、做布料和破碎而不撕裂

撕裂的原因很明确：3DGS 没有拓扑。顶点动画之所以不撕裂，是因为相邻顶点共享边，形变是连续的。而高斯之间没有任何邻接关系，如果对每个高斯独立套一个变换矩阵，相邻两个高斯的变换一旦不同，中间就直接断开。

所以思路只有一个：给高斯找一个共享的连续映射，让所有高斯都从同一个形变场里取位移，而不是各算各的。

Cage Mesh 路线，这是最实用的。先建一个包住物体的低模 cage（可以从 3DGS 表面重建后简化，也可以手动包裹）。然后算每个高斯中心相对 cage 的绑定权重，可以用最近面 barycentric 插值，也可以用调和坐标或 mean value coordinates，后两者更平滑。cage 顶点绑骨骼权重，走引擎现成的蒙皮。运行时流程是：cage 顶点蒙皮变形 → 用调和权重把每个高斯中心变换过去。

这里有个容易漏的点：高斯的旋转和尺度也要跟着变，不能只挪位置。正确做法是取形变场的雅可比矩阵 J，对协方差做 C' = J·C·Jᵀ 的变换，否则物体一拉伸，高斯椭球还是原来的形状，表面会看起来发糊或破洞。

四面体嵌入路线，用于软体和破碎。用 TetGen 之类构建包住物体的四面体网格，对四面体跑 FEM 或 XPBD 弹簧解算，再对内部每个高斯按四面体 barycentric 插值位移和雅可比。这就是「嵌入」的含义——高斯被装进一个可物理求解的笼子里。布料用弹簧质点或 PBD 在表面网格上解，再驱动高斯。破碎则按空间分区把高斯绑到各碎片代理上，每个碎片一个刚体或凸包，碎裂瞬间切换绑定；边界处的高斯要复制到两侧或用 alpha 过渡，否则接缝会露。

纯隐式路线适合人脸表情：学一个神经形变场或直接用 4D 3DGS，不适合硬性骨骼动画，因为骨骼要求精确的刚性变换，神经场做不到那么准。

实时游戏场景的推荐组合：Cage Mesh + 调和权重 + 雅可比协方差变换。它兼容引擎现有蒙皮、布料和形变系统，稳定且好调。只有确实需要软体解算和破碎时才上四面体嵌入。检查撕裂就看一件事：相邻高斯的位移是否连续，权重在空间上有没有跳变。

Q30｜单目视频动捕的脚滑、自相交、抖动怎么修

三个现象的成因各不相同，要分开治，混在一起调必然越调越糟。

脚滑的本质是「脚没有被约束在世界空间」。单目视频里 2D 关键点有噪声，单目深度有歧义，抬脚和落脚的瞬间检测不准，结果就是脚在地上蹭。自相交是因为纯运动学解算没有任何碰撞约束，手可以穿进身体。抖动是逐帧关键点噪声直接传导到骨骼旋转上。

分层处理的顺序很重要：

第一层，输入平滑。用 One-Euro filter 而不是简单 EMA。EMA 会把快速动作也一起拖慢，One-Euro 能按速度自适应，慢动作强平滑、快动作少平滑——这一点对动捕至关重要。

第二层，运动学约束。用引擎的 Two-Bone IK 或 Full Body IK，加一个相等支撑相检测：脚的高度低于阈值、速度也低于阈值，就判定为支撑脚，把它的 IK 目标冻结在世界空间，这就是 foot planting。抬起脚时要 blend 进 blend 出，硬切会跳帧。

第三层，物理约束。自相交靠给角色挂 capsule 或 convex 碰撞体，用 PBD/XPBD 做自碰撞约束，或者用最小距离约束把穿进去的骨节推开。脚滑除了 foot locking，还可以在物理求解器里加摩擦约束，让支撑脚真的「抓地」。

第四层，物理轨迹优化，这才是「结合物理求解器」的正确用法。物理不是运行时接管角色，而是把动捕当作软约束、物理当作硬约束，做一次离线 trajectory optimization：以最小 jerk、最小能量、接触力合规为目标，迭代修正整条轨迹，把穿模和滑步一次性解掉。思路接近 PhysCap、DeepMimic 那一类工作。实时游戏不需要做到这一步，但离线处理一遍质量提升非常明显。

两个高频坑：一是不要先平滑再 IK，顺序错了会加重脚滑，正确顺序是 IK 之后只滤根节点和髋部轨迹，不要滤关键姿态；二是一定要先对齐地面，做法是平面拟合加估计重力方向，否则整段动画都是斜的，后面怎么调都不对。实时够用的组合是 IK + foot locking + capsule 自碰撞 + One-Euro。

Q31｜任意音频实时驱动 BlendShape，还要 60fps 不卡

先把管线讲清楚，再讲怎么保证 60fps。管线本身分三段：

音频前处理：重采样到固定采样率，取 mel 频谱或 MFCC，也可以直接用 wav2vec2 / HuBERT 提取语音特征。用滑动窗口切，比如 200ms 一窗，步长对齐到视觉帧率。关键设计是多语言不能依赖 ASR——一旦接入识别，中文、日文、小语种全都要单独适配。正确做法是直接用语音特征学 viseme，或者用统一的 IPA 音素集加语言条件 embedding。

网络：轻量的 Audio2Face 模型，CNN 或小 Transformer，输出 FACS 动作单元或 viseme 权重，再叠一个情绪向量控制整体表情。参数量控制在几百万级别，能塞进移动端。

后处理：权重曲线平滑、幅度归一化，再程序化叠加眨眼和呼吸，否则纯模型输出会显得很「木」。

60fps 的五个关键点：

  • 推理放旁路线程。音频只有 50 帧/秒的信息量，完全不需要按 60fps 推理。worker 线程或 GPU compute 收音频，主线程只做插值采样。
  • 固定延迟管线。音频天然有缓冲延迟，把整条管线设计成固定延迟（比如 100ms），权重曲线带时间戳，主线程用前后两帧插值，视觉上完全无感。
  • 模型量化。FP16 或 INT8，剪枝，配 ONNX Runtime、NCNN 或 TFLite 跑。
  • 固定输入形状。按固定窗口 batching，避免变长输入触发重编译或动态 shape 降速。
  • 能预烘就预烘。这是保证 60fps 最稳的一条。已知台词、过场动画，全部离线烘成动画 clip，运行时只做混合，零推理；只有玩家自由对话这种真正交互的场景才走实时推理。

验收看三个数：唇音同步误差控制在 40ms 以内基本就看不出来；blendshape 曲线不能有高频抖动；每种目标语言都要有独立测试集，中文的声调和爆破音跟英文差别很大，只靠英文数据训出来会明显对不上口型。

常见问题速查

把四层里最常踩的坑按现象、原因、处理三步收敛，遇到问题先在这里对号。后面接情景题，给一个具体场景判断该怎么做。

一、几何类

模型进引擎后正面亮、背面黑，像被剖开？

面法线内外混翻。统一法线朝外（Unify Normals），翻转错误面后重导入。判断方式：背面剔除打开后从外看有空洞，就是法线朝内。

模型能看，一进 SDF 或体素化流程就报错或塌陷？

网格不水密，有边界边或破洞，体积内外不明确。补洞（Cap Holes）、删内部面，做成封闭 2-流形。注意不是所有破洞都要补，朝下的开口有时是设计本身，要先确认语义。

重拓扑或展 UV 时直接崩掉？

存在非流形：一条边被三个以上面共享，或两个体只靠点、边相连。删多余面、焊接重合点、拆开仅点边相连的部件，再跑重拓扑。

重拓扑后脸部布线比身体还稀疏，剪影发糊？

面数分配没按视觉重要性走。脸是视觉中心，要给足面数撑剪影和表情；否则后续绑定与表情都会失真。

重拓扑后腿部完全没法绑定？

腿部布线不连续，缺少沿肢体走向的环线，关节处没有足够支撑。这类区域要手工重建环线，不能直接吃自动重拓扑结果。

生成模型一减面就破面、塌角？

原网格本身三角面质量差，存在细长三角形、重叠面和零面积面。减面会在这些地方优先塌陷。先做清理（移除重合顶点、删除零面积面、修复自交），再减面。

模型好几个部件互相穿插，内部还残留看不见的面？

生成阶段没有做部件级约束，也没删内部几何。内部面会让体积计算、碰撞和烘焙都出错。按部件检查穿插，做布尔或手工修，内部面直接删掉。

模型导进引擎后尺寸不对，差了一百倍？

单位不一致。导出时源文件按厘米、导入端按米，或者导出没应用缩放变换。导入前统一单位，导出时应用变换并确认轴向设置。

二、渲染约定类

法线贴图一用就凹凸反向，凸变凹、凹变凸？

GL 与 DX 约定不匹配。OpenGL 纹理原点在左下、DirectX 在左上，导致 G 通道符号相反。按目标引擎统一翻转 G 通道，不要逐张图手改，写进导出流程。

模型没贴错图，表面却有细碎噪点、接缝处光影断裂？

UV 分布差加上打了光滑组，法线在接缝处方向跳变。重展 UV、检查法线是否统一，必要时重算法线并明确硬边与软边。

法线贴图进 Unity 后颜色发紫发亮，效果完全不对？

贴图没有被识别为 Normal Map。导入设置里把 Texture Type 改成 Normal map，并把 sRGB 关掉，否则会被当成颜色图解码。

同一张颜色贴图在 DCC 和引擎里色差明显？

色彩空间没对齐。颜色贴图用 sRGB，数据贴图（粗糙度、金属度、法线）用线性。标错会导致整体偏灰或偏亮，且会污染训练标签。

烘焙出来的法线贴图换个角度看就有裂缝？

高低模的切线空间不一致，或 UV 接缝处没有做边缘填充（padding）。统一切线设置，导出时给 UV 接缝留出边距。

三、材质类

生成的贴图一重新打光就脏？

Albedo 里烤进了阴影、高光或 AO。需要去光照（de-lighting），把纯基础色分离出来。扫描件和截屏转的贴图几乎都有这个问题。

同一块表面粗糙度忽高忽低，甚至突然黑一块？

Roughness 数值不一致。同一材质应保持统一区间，局部突变要在贴图层面平滑或重绘。注意是局部黑一块，不是渐变，这种通常是训练残留而不是真实材质。

金属度满屏灰阶，金属和非金属糊成一片？

Metallic 本应接近二值，只在金属边缘有过渡。按材质语义重新阈值化，并把中间灰阶改为对应的 0 或 1。

一张贴图被很多模型复用，材质语义互相冲突？

贴图集式复用会把不同材质的数值混在一起。生成任务里要按材质 ID 分开，不能靠一张图贴所有部件。

导入引擎后金属度和粗糙度显示错位？

通道打包顺序不一致，常见有 ORM、RMA、MRAO 几种排法。按目标管线的顺序重排通道，并在规范里写死，不要靠记忆。

四、数据、算法、评测类

同一批数据训出来的模型，风格与规范互相打架？

数据内部约定不统一，法线 GL 与 DX 混用、PBR 数值标准不一。进训练集前必须做一次全量约定归一，并且把归一规则固化成脚本。

生成结果看着还行，一进引擎就没法用？

缺下游可用性评测。生成质量高不等于可落地，还要测导出干净度、拓扑可绑定性、减面后的质量保持。

模型在某些类别上明显更差？

类别不平衡或该类别样本质量偏低。重采样平衡类别，对低质样本做质量分层或剔除，再单独看这个类别验证集的表现。

数据集看着很大，训练效果却上不去？

有效样本少。大量近重复模型、同一资产的多个视角重复计入、低质或残缺模型占比高。去重加质量分层之后，有效数据量往往只剩一小半。

模型之间只差一点点，评测分数却分不出来？

指标分辨率不够，或者指标与感知不一致。要补下游可用性指标和人工盲测，不能只看单一的几何相似度。

换了一版数据，分数涨了，美术却说更差了？

指标被数据分布带偏。比如新数据里简单样本变多，平均分自然上升。要分组看指标，并按难度和类别分层对比。

情景题：给一个场景，判断该怎么做

下面这些不是查表能答的，要先判断问题落在哪一层，再定动作顺序。每条都带一句如果没有某个条件时的替代做法。

供应商一次交付五万个模型，只给三天，怎么定清洗优先级？

先做统计而不是逐个看。第一遍只跑可自动判定的硬指标：水密、非流形、法线一致性、贴图缺失、单位与缩放。按不合格率排序，先修占比最高的那一类，因为它对整体质量影响最大。三天不够全清是正常的，产出应该是带质量分层的可用子集，而不是一批全都半清的数据。
如果没有自动检测脚本，就先按类别抽样一百个，人工统计不合格类型的分布，再决定先写哪个检测脚本，不要五个都写。

没有现成的水密修复工具，数据又必须进体素流程，怎么办？

先降级方案而不是硬修。不水密的模型不进体素流程，改用多视角渲染加深度图作为替代监督，或者只取水密的那部分做三维监督。同时评估缺口规模，如果破洞集中在少数几类资产，就针对性写补洞脚本，而不是追求全自动。
举一反三：任何必须的预处理能力缺失时，先问能不能绕过这一步换一种表示，其次才是补工具。

只有 CPU 环境，没法训练也没法快速渲染，怎么验证数据可用？

把验证拆成不依赖 GPU 的部分：几何拓扑检查、UV 重叠计算、贴图统计、法线方向判定都是纯数值计算，CPU 完全够用。渲染相关的检查可以抽样少量交给在线环境或直接跳过，用数值指标代替目视。
关键是把可验证的部分先验证掉，不要让整条流程卡在一个不具备的条件上。

算法说指标达标，美术说生成的脸不能用，怎么对齐？

先确认两边说的不是同一件事。算法看的是整体几何与纹理相似度，美术看的是视觉中心有没有面数支撑、剪影是否成立。要把美术的判断翻译成可测指标，比如脸部区域的面密度、眼口鼻区域的曲率误差。然后补一条分区指标，而不是继续用全局平均。
这类分歧基本都来自指标没有分区。

两个团队标注标准不一致，同一批数据标出两种结果，怎么定规范？

先拿二十个争议样本做共同评审，找出分歧点在哪一条定义上，通常是边界情况没有写清楚。然后把定义改写成可判定的规则，附正反例。规范定完要跑一次双盲重标，算一致率，一致率不达标就说明规则还有歧义。
没有人力做双盲时，至少让双方各自标同一批小样本，直接比对差异条目。

要求两万面以内、还要能绑表情，这两条能同时满足吗？

能，但要重新分配面数。两万面里优先保证脸部和关节环线，躯干和配件降密度。先做分区预算表，再按预算重拓扑，而不是先重拓扑再整体减面。
如果预算实在不够，就要提出取舍：减少配件细节，或者降低表情精度要求，把选择权交回需求方。

数据里三成是扫描件，Albedo 自带光照，没有去光照工具？

先把这批数据隔离，不要混进主训练集。可以用它们在几何任务上做监督，纹理任务单独处理。纹理侧的最低成本方案是统一做一次强光下的重渲染，把光照方向归一化，虽不完美但比直接混用可控。
同时评估这部分数据值不值得修，如果只占三成且质量参差，剔除往往比修复更划算。

手上只有原始模型库，没有标注也没有评测集，从零怎么建？

先建质量分层而不是建标签。用自动指标把模型分成可用、待修、废弃三层，再从可用层里按类别和风格抽样，形成小规模评测集。评测集要先于训练集被固定下来，否则后面无法比较。
没有人工标注时，先用规则标注加少量人工抽检，规则标注要能解释，不要用黑盒结果当标签。

产品问：这整条链路从数据到上线，怎么判断先投哪一层、砍哪一层？

先按上下游走一遍，找当前最卡的那一环。如果生成质量已经达标但 TA 返修率居高不下，瓶颈在落地层，应该先投管线自动化而不是继续训模型；如果 bad case 主要是几何破洞和法线错乱，瓶颈在数据层，先投清洗而不是换网络。
判断方法很朴素：拉一张表，每一层写清楚输入、产出、平均耗时和当前合格率，合格率最低、耗时最长的那层就是瓶颈。资源有限时只打瓶颈，不要平均用力——四层都投一点等于四层都没投。
如果连各层的耗时和合格率都拿不出来，第一步不是投钱，是先把度量建起来，否则无法判断投得值不值。

同一件事，对三种角色怎么说

同一个问题要在三种语境里各说一遍，说错对象等于没说。对算法讲数值与分布，对评测讲判定规则与复现步骤，对产品讲影响与交付。

对象关注点表达方式
算法数值分布是否违背假设，会不会污染梯度给统计量、给假设、给对训练的影响
评测怎么判定合格，怎么复现，通过率多少给阈值、给抽样方法、给判定规则
产品与美术看起来怎么样，什么时候能好，要多少成本给现象、给影响、给工期与取舍

示例：金属度贴图满屏灰阶

对算法：金属度通道取值分布偏离二值假设，均值偏低、中间段占比过高，等于把介质反射率混进了导体项，训练时这部分梯度基本是噪声。

对评测：判定规则是取样一百张，统计金属度落在 0.1 到 0.9 区间的像素占比，超过百分之五判不合格；复现步骤是固定随机种子抽样后跑同一段统计脚本。

对产品：这版资产金属感会发灰，看着像塑料不像金属，返工需要重跑一次材质生成，人工修图另算。

同一个结论说三遍不是重复劳动，三句话的接收方不同，动作也不同：算法会去改损失或过滤样本，评测会去补一条判定规则，产品会去调排期。少说一种，这条信息就等于没传到位。

几个职能的日常

这些底层知识落到日常，大致分成五类工作，彼此交接的是数据、结论和资产。

职能每天在做什么交付物
模型侧 看训练曲线与损失，调数据配比，跑消融，翻 bad case，判断是数据问题还是结构问题 训练好的模型、失败样本归因
数据侧 收数据、跑清洗与质检脚本、定标注与命名规范、抽样验收，处理供应商交付的批次 干净可用的训练数据、规范文档
评测侧 建评测集、定指标与阈值、跑新旧对比、人工盲测、写结论与复现步骤 评测报告、可复现的判定规则
落地侧 接需求，把生成资产修到能进引擎，做减面、UV、拓扑与材质规范化，处理性能与兼容 能进项目的资产、管线脚本
产品侧 定需求与优先级，对齐上下游预期，管理排期与取舍，跟踪上线效果与用户反馈，把用户语言翻译成技术动作 需求文档、优先级排序、上线标准、迭代计划

五类工作共享同一套语言：几何是否成立、渲染约定是否统一、材质是否物理正确、数据是否可测。这四条不通，交接就会反复来回。产品侧不直接做这四条，但要确保这四条在上下游之间传得通、对得上。

小结

底层问题决定上层质量：水密/流形/法线决定几何能不能算，OpenGL vs DX 约定决定渲染对不对，PBR 金属工作流决定材质正不正确，这三者合起来决定训练数据是好是坏，最终决定大模型生成出来的 3D 资产能不能真正用起来。

至此四层已经补全：数据层（几何 / 渲染 / 材质 / 清洗）→ 算法层（表示 / 网络 / 训练）→ 评测层（数据质检 + 生成质量）→ 落地层（引擎接入 / TA），外加一条评测与落地反馈回流数据与算法的闭环。这一篇会持续补充，后面做工具、做数据、做算法、做评测时遇到的新问题，都会按这条四层闭环继续往里填。
