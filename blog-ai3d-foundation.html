AI 3D 大模型研究日志（底层 · 数据 · 算法）

2026年9月 · 研究整理 · AI 3D 的底层数据与管线

水密网格 法线约定 PBR 训练数据 多模态3D 数据技术美术

定位：这一篇和前面四篇有什么不同

之前的 Meshy / Tripo / 混元3D / AI生成3D合集，是从应用层记录各家平台的生成效果、功能与局限。这一篇换个角度，往下钻到底层：做 AI 3D 这条链路的人每天在跟哪些底层知识打交道，包括几何、网格、渲染约定、PBR、训练数据质量。

这些底层知识决定了喂给模型的 3D 数据到底是好数据还是坏数据，也决定了模型生成出来的资产能不能真正进引擎、能不能被渲染管线正确显示。下面按四层架构（数据 → 算法 → 评测 → 落地）逐层整理。

四层架构总览

AI 3D 生成是一条四层闭环的数据链，不是单向流水线：数据层 → 算法层 → 评测层 → 落地层，而评测和落地的反馈会回流给数据层与算法层。

层做什么常见分工本日志章节
数据层采集/合成 → 清洗 → 标注 → 配比数据技术美术（Data TA）几何 / 渲染约定 / PBR / 清洗案例
算法层表示 → 网络 → 训练 → 生成大模型算法下方算法层
评测层生成质量 + 数据质量两道评测算法评测 / QA下方评测层
落地层引擎接入 / 修拓扑 / PBR 化 / 管线自动化AI 3D 技术美术几何 / 渲染约定 / PBR

几何与网格：水密、流形、法线一致性

水密（Watertight）指一个网格是封闭的 2-流形，没有边界边、没有破洞，能够明确地包住一个体积。判断标准：每条边恰好被两个面共享，从任意点出发不穿出表面。

  • 为什么重要：体素化（Voxelization）、符号距离场（SDF）、布尔运算、四面体网格、物理碰撞、3D 打印都假设表面是封闭的。很多 3D 生成模型的表示（占用场 Occupancy Field、SDF、tetrahedral）都需要水密输入。
  • 非水密对训练的影响：体积歧义、内外不明确、法线在破洞处乱翻，模型学到的形状会在开口处塌掉或出错。

流形（Manifold）：局部上每个点都像一块平面（圆盘邻域）。非流形常见于：一条边被 3 个以上面共享、两个体只靠一个点或一条边相连（蝴蝶顶点/边）。非流形网格在重拓扑、展 UV、SDF 计算时都会崩。

法线一致性：所有面法线应统一朝外。如果一半朝里一半朝外，光照和体积计算都会错。对训练数据来说，法线方向不一致是脏数据的直接来源。

数据质检第一关：把模型丢进看背面 + 看线框 + 看边界边（boundary edge）三个视图扫一遍，水密/流形/法线问题基本都能暴露。

渲染约定：为什么 OpenGL 和 DirectX 的法线方向不一样

这是最典型的一个底层约定问题。法线贴图用 RGB 三个通道存切线空间法线：R = 切线 X，G = 副切线 Y，B = 法线 Z。OpenGL 和 DirectX 的区别就出在 G（Y/上下）通道上。

根因是纹理坐标原点的约定不同：OpenGL 把纹理坐标原点放在左下角，DirectX 放在左上角。这意味着两张图的 V 轴（竖直方向）是上下相反的。法线贴图既然存的是切线空间的 Y 分量，而 V 轴被翻转，那么同一个朝上的法线，在两种约定里存的 G 通道数值就正好符号相反。

维度OpenGL 约定DirectX 约定
纹理坐标原点左下角 (0,0)左上角 (0,0)
法线贴图 G 通道（Y）朝上（+Y 向上）朝下（+Y 向下，G 取反）
典型引擎Unity（可导入时翻转）Unreal（默认 DX 风格）
用错的表现凹凸反向（凸变凹、凹变凸），在斜射光下、接缝处尤其明显

对训练数据的影响：如果数据库里两种约定的法线贴图混着用、又不做统一翻转，模型会学到互相矛盾的法线方向分布，生成结果的法线会乱，进引擎后光影错乱。所以数据管线里法线贴图约定统一是必做的一步。

PBR 与金属工作流

PBR（Physically Based Rendering）的核心是能量守恒 + 微表面 BRDF，把材质拆成一组物理量：Albedo（基础色）、Metallic（金属度）、Roughness（粗糙度）、Normal（法线）、AO（环境光遮蔽）。

金属工作流（Metallic/Roughness）是当前主流：用一张 Metallic 贴图区分金属 vs 电介质，用 Roughness 控制微表面粗糙度。与之相对的是高光工作流（Specular/Glossiness），Unreal 早期常用，现在更推荐金属工作流。

贴图合理取值 / 判断脏数据的典型表现
Albedo 基础色只含颜色，不含光照/阴影把烘焙光照、阴影、高光烤进颜色图
Metallic 金属度基本是二值：0（电介质）/ 1（金属），过渡区只出现在金属边缘到处是 0~1 的灰阶、金属与非金属边界糊成一团
Roughness 粗糙度0（镜面）~ 1（哑光）连续，但同一材质应统一同一表面粗糙度忽高忽低、突然黑一块/白一块
Normal 法线约定统一（见上一节）GL/DX 混用、接缝处方向翻转

对训练数据的影响：如果训练集的 Albedo 里混着光照残留、Metallic 数值乱、Roughness 突变，模型就会学到光照当材质金属度灰阶粗糙度噪点这些错误模式，生成结果再重新打光就会露馅。

训练数据的好坏：什么让数据训出来是好模型

把前面几节串起来，就是一条数据质量 → 模型质量的因果链。判断一批 3D 训练数据的好坏，基本看这五点：

  • 几何干净：水密、流形、无自相交、无退化三角形、法线统一朝外、面数分布合理（视觉中心给足面数撑剪影）。
  • 贴图物理正确：PBR 数值合理、Albedo 无光照残留、法线约定统一、无接缝、无烘焙阴影残留。
  • UV 布局合理：无重叠、无拉伸、接缝放在不显眼处。
  • 多视角一致：多视图数据（图像→3D）要求不同视角下同一物体的几何/材质一致，否则模型学到矛盾外观。
  • 标注规范：命名、类别、标签一致，方便检索与配比。

一句话总结：好数据 = 几何上可计算（水密/流形/法线一致）+ 材质上物理正确（PBR 数值合理、约定统一）+ 视角上可对齐。这三条任何一条塌了，模型都会把脏当成规律学进去。

训练数据清洗：具体案例

把上面三条标准落到具体动作上，沿几何 → 渲染 → 材质 → 视角 / 标注的主线，每个案例按问题 → 识别 → 清洗 → 对训练的影响展开。

① 几何清洗

案例 1 · 破洞修复（水密化）

  • 问题：扫描或生成的模型有破洞，存在边界边（boundary edge），不是封闭体积。
  • 识别：Max 里用 polyop.getNumOpenEdges 数开放边、高亮边界边，或直接看线框破口。
  • 清洗：补洞（Cap Holes）、删掉内部/多余面，必要时重拓扑成水密体。
  • 影响：SDF / 占用场 / 四面体训练都要求水密；破洞会导致体积歧义，法线在洞口乱翻。

案例 2 · 非流形修复

  • 问题：一条边被 3 个以上面共享，或两个体只靠一个点 / 一条边相连（蝴蝶顶点 / 边）。
  • 识别：流形检测、统计每条边的共享面数。
  • 清洗：删除多余面、焊接重复顶点、拆开仅点 / 边相连的部件。
  • 影响：非流形会让重拓扑、展 UV、SDF 计算直接崩掉。

案例 3 · 法线方向统一

  • 问题：面法线内外混翻，一半朝里一半朝外。
  • 识别：双面光照 + 背面视图，看颜色异常的面。
  • 清洗：统一法线朝外（Unify Normals）、翻转错误面。
  • 影响：法线不一致是脏数据最直接的来源，渲染与体积计算都会错。

② 渲染约定清洗

案例 4 · GL / DX 法线贴图统一

  • 问题：库里混入 OpenGL 与 DirectX 两种约定的法线贴图（绿通道方向相反）。
  • 识别：看绿通道（G）朝上还是朝下，或进引擎对比凹凸方向。
  • 清洗：统一翻转到一种约定 Unreal 用 DX、Unity 用 GL，导入时选对，或批量翻转 G 通道。
  • 影响：约定混用会让模型学到互相矛盾的法线分布，生成结果法线乱、光影错乱。

③ 材质（PBR）清洗

案例 5 · Albedo 去光照

  • 问题：基础色图里烘焙了阴影、高光、AO。
  • 识别：Albedo 上能看到明显明暗 / 阴影区域。
  • 清洗：去光照（de-lighting），用光照估计 / 逆渲染把纯 albedo 分离出来。
  • 影响：光照残留会让模型把打光当成材质，重打光就露馅。

案例 6 · Metallic / Roughness 规范化

  • 问题：metallic 到处是灰阶、roughness 在同一表面突变（忽高忽低、突然黑 / 白一块）。
  • 识别：灰度直方图看异常分布。
  • 清洗：metallic 阈值二值化、roughness 平滑统一。
  • 影响：数值乱会让模型学到错误材质分布（如粗糙度噪点）。

④ 视角 / 标注 / 去重

案例 7 · UV 重叠与拉伸

  • 问题：UV 重叠、拉伸严重、接缝位置不合理。
  • 识别：棋盘格贴图检查拉伸、重叠检测。
  • 清洗：重展 UV、修复重叠、把接缝移到不显眼处。
  • 影响：UV 烂会导致贴图烘焙 / 重投影质量差，接缝处脏。

案例 8 · 多视角一致性

  • 问题：image-to-3D 的多视角图，同一物体在不同视角下材质 / 几何不一致。
  • 识别：跨视角对比同一特征点。
  • 清洗：剔除不一致视角、统一光照环境与相机。
  • 影响：视角不一致会让模型学到矛盾外观，重建产生歧义。

案例 9 · 去重与类别平衡

  • 问题：数据集重复、低质样本、类别不平衡。
  • 识别：哈希去重、质量评分过滤、类别统计。
  • 清洗：去重、过滤低分样本、重采样平衡类别。
  • 影响：类别不平衡会让模型偏向高频类别，生成多样性下降。

九个案例串起来就是一条可落地的清洗流水线：先修几何（水密 / 流形 / 法线）→ 再统一渲染约定（GL/DX 法线）→ 再清材质（去光照 / 数值规范化）→ 最后清 UV / 视角 / 去重。这条流水线跑完，喂给模型的数据才谈得上干净。

算法层：表示、网络与训练

算法层的第一性问题不是网络，而是表示方式（Representation） 同一个3D 生成任务，用什么数据结构来表征形状，直接决定了能生成什么、需要什么数据、以及生成结果能不能干净导出。

表示方式

表示特点对数据的要求
SDF（符号距离场）隐式、连续、水密友好，适合可变形 / 光滑表面；难出复杂拓扑要求水密、法线一致
占用场（Occupancy）0/1 内外，实现简单，但边界不够精确水密、内外明确
四面体网格（Tetrahedral）显式 + 体积，可直接进物理 / 有限元，内存大水密、流形
3D 高斯（3DGS）渲染快、可微，适合新视角合成，但表面不严格一致多视角、多视图对齐
NeRF（神经辐射场）连续体积、光照可学，训练慢、难导出干净 mesh一致多视角、相机位姿

注意表示方式与数据层的强耦合：SDF / 占用场 / 四面体都要求水密输入，这正是前面破洞修复那一系列几何清洗存在的根本原因。

网络结构与训练

  • 扩散模型（Diffusion）：当前 text-to-3D / image-to-3D 主流，逐步去噪生成；
  • Transformer / DiT：多模态对齐、序列建模，常用作条件编码器或骨干；
  • 多视图重建（如 MV-Dream 类）：2D 扩散 + 多视图一致性约束，提升几何一致；
  • 大重建模型（如 LRM 类）：单张 / 少量图直接前馈出 3D，推理快、适合规模化；
  • 训练要素：损失函数（几何损失 / 渲染损失 / 感知损失 / 多视角一致性损失）、噪声与学习率调度、大模型蒸馏、数据配比（类别平衡、质量分层）。

评测层：两道评测与指标

评测层其实有两道：训练前的数据质量评测（决定哪些数据能进训练集），和训练后的生成质量评测（决定模型好不好用）。

生成质量评测

  • 几何质量：水密率、流形率、面数合理性、拓扑干净度，回到数据层那套标准；
  • 纹理质量：PBR 数值合理、无接缝、无光照残留；
  • 与参考相似度：FID（2D 渲染图分布）、CLIP Score（文本-图像对齐）、几何相似度（Chamfer Distance、F-Score）；
  • 主观 / 用户评分：人工评测生成结果的观感与可用性。

下游可用性评测（落地层视角）

  • 能否进引擎：FBX / glTF 导出是否干净、PBR 贴图是否齐全；
  • 能否绑定动画：拓扑是否支持骨骼绑定、蒙皮；
  • 能否重拓扑 / 减面：重拓扑、减面后是否仍保持质量。

数据质量评测（训练前，回流到数据层）

  • 数据质检打分：水密 / 流形 / 法线 / 贴图数值的通过率；
  • 回流作用：这些指标直接决定哪些数据可以进训练集，是评测层回流数据层的第一道闸门。

常见问题速查

把四层里最常踩的坑按现象、原因、处理三步收敛，遇到问题先在这里对号。后面接情景题，给一个具体场景判断该怎么做。

一、几何类

模型进引擎后正面亮、背面黑，像被剖开？

面法线内外混翻。统一法线朝外（Unify Normals），翻转错误面后重导入。判断方式：背面剔除打开后从外看有空洞，就是法线朝内。

模型能看，一进 SDF 或体素化流程就报错或塌陷？

网格不水密，有边界边或破洞，体积内外不明确。补洞（Cap Holes）、删内部面，做成封闭 2-流形。注意不是所有破洞都要补，朝下的开口有时是设计本身，要先确认语义。

重拓扑或展 UV 时直接崩掉？

存在非流形：一条边被三个以上面共享，或两个体只靠点、边相连。删多余面、焊接重合点、拆开仅点边相连的部件，再跑重拓扑。

重拓扑后脸部布线比身体还稀疏，剪影发糊？

面数分配没按视觉重要性走。脸是视觉中心，要给足面数撑剪影和表情；否则后续绑定与表情都会失真。

重拓扑后腿部完全没法绑定？

腿部布线不连续，缺少沿肢体走向的环线，关节处没有足够支撑。这类区域要手工重建环线，不能直接吃自动重拓扑结果。

生成模型一减面就破面、塌角？

原网格本身三角面质量差，存在细长三角形、重叠面和零面积面。减面会在这些地方优先塌陷。先做清理（移除重合顶点、删除零面积面、修复自交），再减面。

模型好几个部件互相穿插，内部还残留看不见的面？

生成阶段没有做部件级约束，也没删内部几何。内部面会让体积计算、碰撞和烘焙都出错。按部件检查穿插，做布尔或手工修，内部面直接删掉。

模型导进引擎后尺寸不对，差了一百倍？

单位不一致。导出时源文件按厘米、导入端按米，或者导出没应用缩放变换。导入前统一单位，导出时应用变换并确认轴向设置。

二、渲染约定类

法线贴图一用就凹凸反向，凸变凹、凹变凸？

GL 与 DX 约定不匹配。OpenGL 纹理原点在左下、DirectX 在左上，导致 G 通道符号相反。按目标引擎统一翻转 G 通道，不要逐张图手改，写进导出流程。

模型没贴错图，表面却有细碎噪点、接缝处光影断裂？

UV 分布差加上打了光滑组，法线在接缝处方向跳变。重展 UV、检查法线是否统一，必要时重算法线并明确硬边与软边。

法线贴图进 Unity 后颜色发紫发亮，效果完全不对？

贴图没有被识别为 Normal Map。导入设置里把 Texture Type 改成 Normal map，并把 sRGB 关掉，否则会被当成颜色图解码。

同一张颜色贴图在 DCC 和引擎里色差明显？

色彩空间没对齐。颜色贴图用 sRGB，数据贴图（粗糙度、金属度、法线）用线性。标错会导致整体偏灰或偏亮，且会污染训练标签。

烘焙出来的法线贴图换个角度看就有裂缝？

高低模的切线空间不一致，或 UV 接缝处没有做边缘填充（padding）。统一切线设置，导出时给 UV 接缝留出边距。

三、材质类

生成的贴图一重新打光就脏？

Albedo 里烤进了阴影、高光或 AO。需要去光照（de-lighting），把纯基础色分离出来。扫描件和截屏转的贴图几乎都有这个问题。

同一块表面粗糙度忽高忽低，甚至突然黑一块？

Roughness 数值不一致。同一材质应保持统一区间，局部突变要在贴图层面平滑或重绘。注意是局部黑一块，不是渐变，这种通常是训练残留而不是真实材质。

金属度满屏灰阶，金属和非金属糊成一片？

Metallic 本应接近二值，只在金属边缘有过渡。按材质语义重新阈值化，并把中间灰阶改为对应的 0 或 1。

一张贴图被很多模型复用，材质语义互相冲突？

贴图集式复用会把不同材质的数值混在一起。生成任务里要按材质 ID 分开，不能靠一张图贴所有部件。

导入引擎后金属度和粗糙度显示错位？

通道打包顺序不一致，常见有 ORM、RMA、MRAO 几种排法。按目标管线的顺序重排通道，并在规范里写死，不要靠记忆。

四、数据、算法、评测类

同一批数据训出来的模型，风格与规范互相打架？

数据内部约定不统一，法线 GL 与 DX 混用、PBR 数值标准不一。进训练集前必须做一次全量约定归一，并且把归一规则固化成脚本。

生成结果看着还行，一进引擎就没法用？

缺下游可用性评测。生成质量高不等于可落地，还要测导出干净度、拓扑可绑定性、减面后的质量保持。

模型在某些类别上明显更差？

类别不平衡或该类别样本质量偏低。重采样平衡类别，对低质样本做质量分层或剔除，再单独看这个类别验证集的表现。

数据集看着很大，训练效果却上不去？

有效样本少。大量近重复模型、同一资产的多个视角重复计入、低质或残缺模型占比高。去重加质量分层之后，有效数据量往往只剩一小半。

模型之间只差一点点，评测分数却分不出来？

指标分辨率不够，或者指标与感知不一致。要补下游可用性指标和人工盲测，不能只看单一的几何相似度。

换了一版数据，分数涨了，美术却说更差了？

指标被数据分布带偏。比如新数据里简单样本变多，平均分自然上升。要分组看指标，并按难度和类别分层对比。

情景题：给一个场景，判断该怎么做

下面这些不是查表能答的，要先判断问题落在哪一层，再定动作顺序。每条都带一句如果没有某个条件时的替代做法。

供应商一次交付五万个模型，只给三天，怎么定清洗优先级？

先做统计而不是逐个看。第一遍只跑可自动判定的硬指标：水密、非流形、法线一致性、贴图缺失、单位与缩放。按不合格率排序，先修占比最高的那一类，因为它对整体质量影响最大。三天不够全清是正常的，产出应该是带质量分层的可用子集，而不是一批全都半清的数据。
如果没有自动检测脚本，就先按类别抽样一百个，人工统计不合格类型的分布，再决定先写哪个检测脚本，不要五个都写。

没有现成的水密修复工具，数据又必须进体素流程，怎么办？

先降级方案而不是硬修。不水密的模型不进体素流程，改用多视角渲染加深度图作为替代监督，或者只取水密的那部分做三维监督。同时评估缺口规模，如果破洞集中在少数几类资产，就针对性写补洞脚本，而不是追求全自动。
举一反三：任何必须的预处理能力缺失时，先问能不能绕过这一步换一种表示，其次才是补工具。

只有 CPU 环境，没法训练也没法快速渲染，怎么验证数据可用？

把验证拆成不依赖 GPU 的部分：几何拓扑检查、UV 重叠计算、贴图统计、法线方向判定都是纯数值计算，CPU 完全够用。渲染相关的检查可以抽样少量交给在线环境或直接跳过，用数值指标代替目视。
关键是把可验证的部分先验证掉，不要让整条流程卡在一个不具备的条件上。

算法说指标达标，美术说生成的脸不能用，怎么对齐？

先确认两边说的不是同一件事。算法看的是整体几何与纹理相似度，美术看的是视觉中心有没有面数支撑、剪影是否成立。要把美术的判断翻译成可测指标，比如脸部区域的面密度、眼口鼻区域的曲率误差。然后补一条分区指标，而不是继续用全局平均。
这类分歧基本都来自指标没有分区。

两个团队标注标准不一致，同一批数据标出两种结果，怎么定规范？

先拿二十个争议样本做共同评审，找出分歧点在哪一条定义上，通常是边界情况没有写清楚。然后把定义改写成可判定的规则，附正反例。规范定完要跑一次双盲重标，算一致率，一致率不达标就说明规则还有歧义。
没有人力做双盲时，至少让双方各自标同一批小样本，直接比对差异条目。

要求两万面以内、还要能绑表情，这两条能同时满足吗？

能，但要重新分配面数。两万面里优先保证脸部和关节环线，躯干和配件降密度。先做分区预算表，再按预算重拓扑，而不是先重拓扑再整体减面。
如果预算实在不够，就要提出取舍：减少配件细节，或者降低表情精度要求，把选择权交回需求方。

数据里三成是扫描件，Albedo 自带光照，没有去光照工具？

先把这批数据隔离，不要混进主训练集。可以用它们在几何任务上做监督，纹理任务单独处理。纹理侧的最低成本方案是统一做一次强光下的重渲染，把光照方向归一化，虽不完美但比直接混用可控。
同时评估这部分数据值不值得修，如果只占三成且质量参差，剔除往往比修复更划算。

手上只有原始模型库，没有标注也没有评测集，从零怎么建？

先建质量分层而不是建标签。用自动指标把模型分成可用、待修、废弃三层，再从可用层里按类别和风格抽样，形成小规模评测集。评测集要先于训练集被固定下来，否则后面无法比较。
没有人工标注时，先用规则标注加少量人工抽检，规则标注要能解释，不要用黑盒结果当标签。

产品问：这整条链路从数据到上线，怎么判断先投哪一层、砍哪一层？

先按上下游走一遍，找当前最卡的那一环。如果生成质量已经达标但 TA 返修率居高不下，瓶颈在落地层，应该先投管线自动化而不是继续训模型；如果 bad case 主要是几何破洞和法线错乱，瓶颈在数据层，先投清洗而不是换网络。
判断方法很朴素：拉一张表，每一层写清楚输入、产出、平均耗时和当前合格率，合格率最低、耗时最长的那层就是瓶颈。资源有限时只打瓶颈，不要平均用力——四层都投一点等于四层都没投。
如果连各层的耗时和合格率都拿不出来，第一步不是投钱，是先把度量建起来，否则无法判断投得值不值。

同一件事，对三种角色怎么说

同一个问题要在三种语境里各说一遍，说错对象等于没说。对算法讲数值与分布，对评测讲判定规则与复现步骤，对产品讲影响与交付。

对象关注点表达方式
算法数值分布是否违背假设，会不会污染梯度给统计量、给假设、给对训练的影响
评测怎么判定合格，怎么复现，通过率多少给阈值、给抽样方法、给判定规则
产品与美术看起来怎么样，什么时候能好，要多少成本给现象、给影响、给工期与取舍

示例：金属度贴图满屏灰阶

对算法：金属度通道取值分布偏离二值假设，均值偏低、中间段占比过高，等于把介质反射率混进了导体项，训练时这部分梯度基本是噪声。

对评测：判定规则是取样一百张，统计金属度落在 0.1 到 0.9 区间的像素占比，超过百分之五判不合格；复现步骤是固定随机种子抽样后跑同一段统计脚本。

对产品：这版资产金属感会发灰，看着像塑料不像金属，返工需要重跑一次材质生成，人工修图另算。

同一个结论说三遍不是重复劳动，三句话的接收方不同，动作也不同：算法会去改损失或过滤样本，评测会去补一条判定规则，产品会去调排期。少说一种，这条信息就等于没传到位。

几个职能的日常

这些底层知识落到日常，大致分成五类工作，彼此交接的是数据、结论和资产。

职能每天在做什么交付物
模型侧 看训练曲线与损失，调数据配比，跑消融，翻 bad case，判断是数据问题还是结构问题 训练好的模型、失败样本归因
数据侧 收数据、跑清洗与质检脚本、定标注与命名规范、抽样验收，处理供应商交付的批次 干净可用的训练数据、规范文档
评测侧 建评测集、定指标与阈值、跑新旧对比、人工盲测、写结论与复现步骤 评测报告、可复现的判定规则
落地侧 接需求，把生成资产修到能进引擎，做减面、UV、拓扑与材质规范化，处理性能与兼容 能进项目的资产、管线脚本
产品侧 定需求与优先级，对齐上下游预期，管理排期与取舍，跟踪上线效果与用户反馈，把用户语言翻译成技术动作 需求文档、优先级排序、上线标准、迭代计划

五类工作共享同一套语言：几何是否成立、渲染约定是否统一、材质是否物理正确、数据是否可测。这四条不通，交接就会反复来回。产品侧不直接做这四条，但要确保这四条在上下游之间传得通、对得上。

产品团队视角：全链路上下游

前面四层是从技术侧看链路，产品团队要把这条链路从上游到下游串起来，回答三个问题：做什么、先做什么、做完值不值。产品不必懂每一层的实现细节，但必须懂每一层的输入、输出、瓶颈和成本，否则排期和取舍就是拍脑袋。

链路阶段上游输入本层产出下游要什么产品关注点
数据层（最上游） 原始模型库、扫描件、供应商交付 清洗后、约定统一的训练数据 算法层要可计算、分布合理的数据 数据从哪来、采购/爬取/合成的成本、清洗周期、数据质量天花板在哪
算法层 训练数据 + 计算资源 可生成 3D 资产的模型 评测层要可量化的生成结果 用什么表示（决定能生成什么）、训练周期与算力成本、效果上限在哪
评测层 生成结果 + 评测集 质量结论与 bad case 归因 产品要上线决策，数据/算法要回流方向 上线标准是什么、指标和人工感受是否对齐、bad case 主要落在哪一层
落地层 生成的原始资产 能进引擎、可绑定、可渲染的资产 美术/项目要直接可用的资产 TA 返修率多少、人工修一个要多久、值不值得自动化、性能是否达标
用户/市场（最下游） 上线后的资产与功能 用户反馈、使用数据、付费转化 回流给产品定下一步优先级 用户能不能用、愿不愿意付费、和竞品差在哪、下一步该补哪一层

产品团队每天在问的几个问题

1. 这条链路的瓶颈在哪一层？是数据不够干净、算法效果上不去、评测分不出来、还是落地返修率太高？瓶颈决定投入方向，不是每一层都要同时投。

2. 每一层的成本和周期是多少？清洗一万个模型要几天、训一版要几张卡几天、TA 修一个资产要几小时。没有这些数，排期和定价都是空的。

3. 上下游的接口约定清楚了吗？数据交给算法时格式是什么、算法交给评测时输出什么、评测结论怎么回流数据和算法。接口不清楚，交接就反复来回，成本全耗在沟通上。

4. 用户反馈落回哪一层？用户说"生成的不像"，到底是数据分布不对、算法表示不行、还是评测标准没覆盖？要能把用户语言翻译成具体的技术动作，而不是笼统地说"再优化一下"。

一句话：产品团队是这条链路的翻译官和调度员——把上游的数据/算法能力翻译成下游的用户价值，把下游的用户反馈翻译成上游的迭代动作。上下游对不上，技术做得再深也落不了地；上下游打通了，每一层的投入才知道值不值。

小结

底层问题决定上层质量：水密/流形/法线决定几何能不能算，OpenGL vs DX 约定决定渲染对不对，PBR 金属工作流决定材质正不正确，这三者合起来决定训练数据是好是坏，最终决定大模型生成出来的 3D 资产能不能真正用起来。

至此四层已经补全：数据层（几何 / 渲染 / 材质 / 清洗）→ 算法层（表示 / 网络 / 训练）→ 评测层（数据质检 + 生成质量）→ 落地层（引擎接入 / TA），外加一条评测与落地反馈回流数据与算法的闭环。这一篇会持续补充，后面做工具、做数据、做算法、做评测时遇到的新问题，都会按这条四层闭环继续往里填。
